# Lucid

Voice-first notes app. Notes are markdown, organized by `#tags`, with voice notes attached. Read `docs/product.md` before building features, UI or copy. If a request conflicts with it, raise it instead of guessing. Read `docs/status.md` to see what is built, what is stubbed, known gaps and gotchas, and keep it current when you change the state of the project.

@AGENTS.md

## Stack

- React Native with Expo (SDK 57), TypeScript. A development build is required (`expo-speech-recognition` has native code); see `docs/ios-dev-build.md`.
- ESLint (`eslint-config-expo`) and Prettier

## Commands

```bash
npm start           # Metro dev server; open the installed development build (Expo Go cannot load this app)
npm run check       # typecheck + lint + format check + tests
npm test            # Jest only (jest-expo preset, Testing Library)
npm run test:watch  # Jest in watch mode
npm run format      # apply Prettier
```

## Layout

- `App.tsx` (wraps the app in `GestureHandlerRootView`) and `src/app/AppFlowProvider.tsx` (flow state). `src/navigation/{NotesNavigator,notesRoutes}.tsx`, `src/screens/` (`NoteListScreen`, `NoteEditorScreen`, `NoteEditorWithVoice`, `NoteSearchPanel`, `RecentlyDeletedScreen`, `SettingsScreen`), `src/components/` (shared UI: rows, `NotesDrawer`, `DrawerIcons`, `TagSortMenu`, `OverflowMenu`, `VoiceNoteCarousel`, `VoiceAttachmentCard`, `RecordingPanel`, `TagSuggestionBar`, ...), `src/hooks/` (`useNotes`, `useNoteSession`, `useNoteEditor`, `useLegacyMigration`, `useSettings`, `useDayMarker`, `useVoiceRecorder`, `useKeyboardInset`, `useDrawerGesture`, `useDrawerProgress`, ...), `src/services/` (`notesStorage`, `legacyImport`, `recordingFiles`, `settingsStorage`, `dayMarker`, `transcription`, `shareRecording`, `clipboard`), `src/utils/` (pure helpers: `note*`, `markdown*`, `inlineTags`, `tags`, `tagSuggestions`, `today`, `relativeTime`, ...), `src/types/recording.ts`, `src/theme/`, `src/test/` (test helpers such as `fakeFileSystem`, `fakeKeyboard`, `bodyText`), `src/dev/EditorSpikeScreen.tsx` (dev-only editor spike harness, `__DEV__` guarded, removal pending), and `jest.setup.ts` at the root. See the file map in `docs/status.md`.
- Navigation is React Navigation's native stack (`src/navigation/NotesNavigator.tsx`): `Notes` (the note list, with the drawer as a component of `NotesRoute`, not a navigator) is the root, and `Editor`, `Settings` and `RecentlyDeleted` are pushed over it (`src/navigation/notesRoutes.tsx`); there is no screen state switch in `App.tsx`. These four routes are the approved set (`Search` was a fifth route from 2026-10-18; it was removed on 2026-10-20 in favour of inline search inside `NotesRoute`); do not add routes or another navigation library without asking. Flow state lives in `src/app/AppFlowProvider.tsx` (`useAppFlow`): the launch rule (`noteLaunchTarget`, inside the launch gate with the one-time `migrateLegacyDreams` import via `useLegacyMigration` and a `LAUNCH_CAP_MS` cap), the notes (`useNotes`), the list view, the open note (`useNoteSession`) and leaving the editor. Expo Router (suggested by boilerplate in `AGENTS.md`) is not used.

## Working rules

- Run `npm run check` before calling any task done, and report failures instead of hiding them.
- Tests are Jest files next to the code (`*.test.ts` / `*.test.tsx`). Add or update tests with behavior changes. Native modules are mocked in tests; `src/test/fakeFileSystem.ts` is a faithful in-memory `expo-file-system` (async copy/move, no overwrite, failure injection); storage changes need careful tests with it.
- Add dependencies with `npx expo install <package>`, and prefer Expo modules over third-party libraries.
- Use the vocabulary in `docs/product.md` (Note, Title, Tag, Body, Voice note, Transcript, Today view, Todo view, Untagged view, Pinned, Recently Deleted, Drawer, Search) in UI copy, code and data models. New code does not use Journal, Entry, Dream, Life, Emotion or Draft; those are retired (see "Retired terms and migration" in `docs/product.md`) and survive only in the migration reader (`src/services/legacyImport.ts`), in migrated data, and in the on-disk names kept on purpose (see Safety rules).
- Use `SafeAreaView` from `react-native-safe-area-context`, not `react-native`.
- UI copy is plain language. No psychological or Jungian terms, no interpretation of notes, no streaks, scores or gamification.
- Do not build anything under "Not in scope yet" in `docs/product.md` (AI features, tasks as a feature, nested tags, markdown beyond headings, lists, checkboxes, bold and italic, automatic purge of Recently Deleted, threads, roundups, explore view, desktop) unless asked. The Todo view only lists notes that contain plain-markdown checkboxes; do not add due dates, reminders or completion tracking.
- A note's title, preview, tags and Todo flag are derived from its body by pure functions in `src/utils/`; they are never stored. Read tags only through `inlineTags` (never hand-roll a `#` regex). Do not store a title or tags field on a note.
- Device access and persistence live behind hooks and services (`useVoiceRecorder`, `useNoteSession`, `services/notesStorage.ts`), not in screens. Notes are stored locally; transcription is on-device only (no audio or text leaves the phone). Storage layout and save order are in the storage section of `docs/status.md`. Safety rules:
  - Notes. The only app-initiated paths that delete files of notes data are: (1) Delete forever, for the one note the user chose to delete from Recently Deleted: every audio file that note lists inside `notes/`, each only if its stored file name is a plain name, resolves inside `notes/`, and no recording of any other note references it, then the index entry (index written last, so a note is never unlisted while its audio remains); (2) Empty Recently Deleted, which is only a loop of case (1) over the notes that have `deletedAt`; (3) the rollback of a failed save, which deletes only the file copies that same save just made (nothing previously stored); (4) discarding a recording that was never saved, or the cache file of a recording once it has been copied into `notes/` and indexed, which deletes only that cache file; (5) when the user leaves a note, the voice notes they closed in it (held recordings) are permanently deleted from `notes/`, each only if its stored file name is a plain name, resolves inside `notes/`, no recording of any other note references it, and it is not a legacy-origin recording. Cases (3) and (4) apply only to files the app created and never stored; case (5) deletes stored files the user explicitly closed. Nothing else. Moving a note to Recently Deleted (soft delete) sets `deletedAt` in the index and never deletes a file; Restore clears `deletedAt`. There is no automatic purge, ever; adding one needs an explicit user decision and a change to this list. Delete forever scrubs the text of the deleted note from `notes.json.bak` and `notes.json.tmp` but leaves `notes.corrupt-<ts>.json` copies alone (they exist only after a damage event), and the docs disclose this. Closing a stored voice note moves the recording to a hold area (`heldAt` on the recording in the index, an index-only write, with undo until the note is left); no file is deleted on close, only by case (5) when the note is left.
  - Notes live in `notes.json` (index, written atomically via a temp file; `notes.json.bak` recovery copy; an unreadable index means refuse to write, and the damaged file is kept as `notes.corrupt-<ts>.json`), with voice note audio in `notes/`. All writes go through `services/notesStorage.ts`.
  - `dreams.json`, `dreams/` and their safety copies are read-only legacy data. Nothing may modify or delete them except the migration reader, and the migration reader only reads them (it never writes to or removes them). The import marker (`migrated.json`) is the only file the migration writes besides `notes.json` and `notes/`.
  - The day marker file (the date the user last finished or skipped the launch note) and `settings.json` live beside the notes index and are never deleted (only overwritten). They keep the names `no-dream.json` (key `noDreamDate`) and `settings.json` key `autoOpenDreamCapture` on purpose (existing user data); do not rename them. They fail open: a missing or unreadable file means not done / defaults, and a failed write never reaches the UI.
  - Only `src/services/notesStorage.ts` and `src/services/recordingFiles.ts` call `.delete(` on a file. `src/app/trashActions.audit.test.ts` guards that only the provider calls `deleteForever`/`emptyTrash`, and `src/app/noLegacyWriters.test.ts` guards that nothing writes the legacy stores. Do not add `.delete(` calls elsewhere.
- The editor's bottom dock (suggestion bar above the toolbar) is lifted above the keyboard by `NoteEditorScreen`: on iOS `KeyboardAvoidingView` (`behavior="padding"`) does it; on Android, where edge-to-edge means the window does not resize, `useKeyboardInset` gives the dock a bottom padding of keyboard height plus the bottom safe-area inset (the inset alone when the keyboard is closed). Do not add `KeyboardAvoidingView` behaviour on Android or measure the keyboard elsewhere. Tests drive the keyboard with `src/test/fakeKeyboard.ts`.
- Voice notes in the editor are shown as stacked cards by `VoiceNoteCarousel` (`VoiceAttachmentCard` each); use it rather than a new list.
- `OverflowMenu` is an in-screen overlay, not a `Modal`. On Android, hardware back closes the open menu first, before the screen's back.
- `App.tsx` is wrapped in `GestureHandlerRootView` (swipe actions use `react-native-gesture-handler`'s `Swipeable`, in `SwipeNoteRow` for note rows and the shared `SwipeActionRow`). Jest needs `jest.setup.ts` (listed in `package.json` `jest.setupFiles`), which imports `react-native-gesture-handler/jestSetup`.
- Keep changes small. The default branch is `main`. All work happens on a feature branch; never commit directly to `main`. Feature branches may be pushed to `origin`; changes reach `main` only through a pull request from a feature branch, which the user reviews and merges. Never push to `main`, never merge a PR yourself, never force-push, and never delete remote branches.
- Never create or edit `ios/` or `android/` by hand; configure native behavior in `app.json`.
