## 1. Where it stands

Lucid is a voice-first notes app: markdown notes with inline `#tags`, voice notes attached to a note, a note list with a drawer of smart views, Recently Deleted, search, and a one-time import of the earlier dreams and journals data. The notes-model work (chunks 1 to 8) is built and covered by Jest, and the old dream and journal code is deleted. **The user tried chunk 9 only (drawer with parallax, left-edge swipe, Today default, inline search with highlighting, Today = created or updated today) on the phone and accepted it on 2026-10-20 ("Tested the changes, accepted"; no per-check detail recorded). Everything else under "What works today" (launch and resume rule, editor, voice notes and transcription, import, trash and restore, row swipe, and anything outside chunk 9) has no recorded device result and is Jest only. The chunk-10 work (icons, sort menu, date header, Recently Deleted dropdown row) is not yet checked on a device.** The only per-check device results on record come from the retired live-text build (Android: audio quality fine, long text scrolls, airplane mode works, no beeps at restarts) and say nothing about the current app. iOS has never been run (the paid Apple Developer account is pending). The 6c editor spike items and the other device checks in section 6 remain open.

**Markdown feature (2026-10-21, branch `feat/markdown`): nothing in it has a device result yet; every test is Jest only.** It adds styled editing for headings 1 to 3, bold, italic, lists, checkboxes, rules, inline code, code blocks, links, images and `[[note]]` links; a reading view; mode switching; the "Load images from the web" setting; following `[[note]]` links with a Back trail; and the `[[` title picker. See section 2 for what exists, section 6 for the device-check list (6c-2), and `docs/product.md` (Notes and markdown) for the behaviour and the privacy disclosure for images.

## 2. What works today

All of this is built, mounted from `App.tsx`, and tested in Jest. **The only device result on record for the current app is the user's acceptance of chunk 9 only (drawer with parallax, left-edge swipe, Today default, inline search with highlighting, Today = created or updated today) on 2026-10-20, with no per-check detail; everything else here, and the chunk-10 work, has no recorded device result and is Jest only.**

- **Launch and resume** (`src/app/AppFlowProvider.tsx`, `src/utils/noteLaunch.ts`, `src/utils/noteResume.ts`, `src/hooks/useToday.ts`). A cold start waits until the stores and the one-time import have loaded, then opens a new empty note on top of the list (setting on, day not settled, notes index readable) or shows the list. Returning to the app on a different day raises `resumeNewDayToken`; one effect consumes each token once and, if `shouldResumeNewDay` allows it (launch decided, notes loaded and readable, setting on, day not settled, no open note, no running leave/delete/trash action, not already on the editor, navigation ready), pushes a new launch note over the current screen (the list, Settings or Recently Deleted; with search open on the list the search state is kept). Leaving it returns to that screen. An empty launch note marks the day done through the normal leave path. "Day settled" is derived from the notes and the day marker (section 3).

The view is session-only and starts at Today, and returns to Today if the selected tag disappears. The launch rule (`dayDone`) deliberately still counts notes created today, not edited today. Chunk 9 (drawer, edge swipe, Today default, Today = created or updated today) was accepted by the user on the phone on 2026-10-20, individual checks not recorded; the chunk-10 parts (icons, sort menu, date header, Recently Deleted dropdown row) are not yet checked on a device. - **Editor, markdown and autosave** (`NoteEditorScreen`, `NoteEditorWithVoice`, `NoteBodyInput`, `useNoteEditor`, `useNoteSession`, `src/utils/markdownEdit.ts`, `markdownLines.ts`). One page creates and edits every note. The title is derived from the body (`noteTitle`). The body is a multiline `TextInput` with nested styled `<Text>` runs (`STYLE_LEVEL = 'full'`: sized headings 1 to 3, bold, italic, bullets, numbered lists, checkboxes, rules, dimmed markers, strike-through on checked items, monospace code on a muted background for inline code and fenced blocks, underlined accent links and `[[wikilinks]]`; bodies over `STYLE_MAX_CHARS` = 20000 are not styled in the editing field, and the reading view has no such cap). Enter continues a list item (a numbered item renumbers the following items of its run) and Enter on an empty item exits the list (detected by diffing the text, not by key events). The toolbar (`NoteToolbar`) is mounted only in editing and has six cells in this order: Undo, Redo (`useEntryHistory`), Hide keyboard (`KeyboardHideIcon`; hint "Stops editing and shows the note."), Record voice note, Add tags and the List controls cell (`ListIcon`; label "List controls", hint "Shows list buttons in place of the keyboard.", or "Shows the keyboard again." while selected; selected while the list panel is open) which swaps the keyboard for `ListControlsPanel` (see the list panel paragraph in section 6). In reading, `RecordFab` (label "Record voice note", hint "Starts a voice note.", bottom right, `NEW_NOTE_FAB_SIZE`, accent colour, elevation 4 shadow) starts a voice note like the toolbar mic; it is not rendered while editing, recording or locked, or while the recording panel or voice sheet is open. Autosave debounces at 1000 ms with a 10 s maximum wait (`useNoteSession`). The "..." menu (`OverflowMenu`) has Pin / Unpin and "Delete note". Leaving always goes through the provider's `leaveEditor`, which saves first; a failed save shows "Couldn't save your note" with Keep editing / Leave anyway and the text stays on screen. - **Markdown structure and reading view** (`src/utils/markdownSpans.ts`: fenced blocks, rules and inline spans; `markdownLines.ts`: the line tokenizer, shared by the editor and the reading view; `markdownBlocks.ts`: one block per source line; `NoteReadingView`, `ReadingBlockRow`, `ReadingImage`, `readingStyles`). - **Mode switching** (`src/hooks/useNoteMode.ts`). The mode is `reading` or `editing`; a pure reducer plus timers. A keyboard hide ends editing only if no show or focus follows within `HIDE_DEBOUNCE_MS`; entering by tap falls back to reading if the input has not focused within `FOCUS_GRACE_MS`; hide events are ignored for `REMOUNT_GRACE_MS` after the body input remounts (`NoteBodyInput.onRemount`: Enter on a list item, undo, tag or `[[` pick, toolbar edits remount it). Blur alone changes nothing, so a hardware keyboard stays in editing until Hide keyboard is tapped (`done()` is the Hide keyboard path). Leaving editing calls `history.onBodyBlur()` and `editor.markBlurred()`. **The three constants are PROVISIONAL (150, 800 and 400 ms) and have not been tuned on a device.** List panel (chunks 5a and 5d, wired): `useNoteMode` also holds `panel`/`swapUntil` (`panelOpen`/`panelClose` actions; hides are ignored while the panel is open and for `SWAP_GRACE_MS` = 600 after it opens or closes; a `keyboardShow` with height > 0 closes the panel, height 0 is ignored), and `useListPanel` (`src/hooks/useListPanel.ts`) runs the keyboard/panel swap (`PANEL_REFOCUS_DELAY_MS` 50, `CARET_HIDE_MS` 150, `PANEL_BLUR_BEFORE_FOCUS` Android only). All PROVISIONAL; real keyboard behaviour is NOT verified by Jest, and Android is entirely unverified.
- **List depth in the reading view** (2026-10-23, branch `feat/indent-a`): depth is relative, not `width / 2`: `listIndentDepths` (`markdownLines.ts`) keeps a stack of indent widths (tab = `INDENT_WIDTH` = 4 columns), so 0/2/4 and 0/4/8 spaces both give 0/1/2 and a lone indented first item is depth 1; a non-list line resets it. `INDENT_PER_DEPTH` is 28 pt. Visual widths are not verified on a device.
- **Editing indent unit** (2026-10-23, branch `feat/indent-b`, on `feat/indent-a`): `INDENT_UNIT` is 4 spaces. Outdent (`outdentListIndent` in `markdownEdit.ts`) moves a list line to `max(parentWidth, width - 4)`, never below 0, where `parentIndentWidths` (`markdownLines.ts`) gives the nearest shallower indent above it in the same list block; a non-list line loses one tab or up to 4 spaces. Enter on an empty nested item outdents by the same rule, then drops the marker at indent 0. `markdownList.ts` uses the shared `indentWidth` (tab = 4). No migration: older 2-space notes keep working and their text is never rewritten on load; only lines the user indents, outdents or presses Enter on change. Known quirk: indenting a top-level line right after a 2-space child nests it under that child (4 under 2), and outdenting then lands on the child's indent (2), not back at 0. 4 spaces while editing is NOT verified on a device.
- **Links, images and wikilinks** (`src/utils/safeUrl.ts`, `src/services/openLink.ts`, `src/utils/noteLinks.ts`, `src/hooks/useTitleIndex.ts`, `WikiLinkSuggestionBar`, `AppFlowProvider.followNoteLink`). `safeUrl` is the allow-list: web links `http://` or `https://` only (no whitespace or control or zero-width characters, no userinfo, backslash or empty host, at most 2048 characters); images `https://` only, with `imageUrlStatus` giving `ok`, `needs-https` or `invalid`. `openWebLink` opens a link with `Linking.openURL` (no `canOpenURL`), never throws, and a refusal shows the alert "Couldn't open this link" (`LINK_COPY`). `ReadingImage` uses the plain `uri` source (no cache option or headers) and loads only when the `loadImages` setting is on or the reader taps the placeholder; placeholders: "Tap to load", "This image needs https", "Can't show this image", "Couldn't load this image. Tap to try again." (a retry remounts the `Image`); the aspect ratio comes from `onLoad`'s `source` size. Wikilinks resolve against the title index of live notes (title lower-cased, whitespace collapsed; newest `updatedAt` wins, then smaller id; Untitled notes left out; the open note enters with its unsaved body). `followNoteLink` locks the editor, reads the notes fresh (twice if the first load fails; failure shows "Couldn't open that note"), saves and leaves the current note, then opens the target or `openNew({ body: title })` in place, without changing route; it announces `Opened "title"` or `Created "title"`. Restore keeps the user on Recently Deleted with a `Restored "title".` line and a screen-reader "Restored"; the note is not opened. An Empty that reports 0 deleted with no failed id is treated as a failure.

**State ownership.** `AppFlowProvider` owns the notes list (`useNotes`), the open note session (`useNoteSession`), settings, the day marker, `useToday`, the legacy migration, transcription, the launch and resume logic and every trash action (`restoreNote`, `requestDeleteForever`, `requestEmptyTrash`, `pinNote`, `trashNote`), including the `trashBusy` guard (a ref plus state, held from the first tap through the confirm and the operation, and refused while a note is open, a leave is running or the index is unreadable) and `trashNotice`. Wording is in `FLOW_COPY` and `TRASH_COPY`, exported from the provider. The routes only pass these through. Only the provider calls `deleteNoteForever` and `emptyRecentlyDeleted`, and only after the dialog's confirm button; `src/app/trashActions.audit.test.ts` pins this and that no screen, component or route imports a write function from `notesStorage`.

**Storage layout** (everything is under `Paths.document`, resolved on every call because the path can change between app updates on iOS; only the audio **file name** is stored, never a full path):

- `notes.json`: the index, `{ version: 1, notes }`. A note carries its body, timestamps, optional `deletedAt` (in Recently Deleted), pinned state and its recordings.
- `notes.json.bak`: best-effort copy of the previous index, made before a commit only when the current index has content. On Delete forever it is instead rewritten from the new list so the removed text does not survive in it.
- `notes.json.tmp`: the staging file of a commit.
- `notes.corrupt-<timestamp>.json`: a copy of an unparseable index, made at most once per app session. Never deleted by the app.
- `notes/`: audio of notes, one file per recording, never overwriting an existing name.
- `migrated.json`: the import marker (ids and counts only, never note text).
- `settings.json`: `autoOpenDreamCapture` (the on-disk key of "Open a new note on launch"; kept so existing toggles and downgrades are not reset), `onlineTranscription`, `loadImages` (a boolean; missing, damaged or non-boolean means false, fail closed) and `tagSort` (`'alpha'` or `'count'`; anything else, or a damaged file, gives `'alpha'`, fail open). Each key is validated on its own; a damaged file falls back to launch note on, online transcription off and images off. Writes keep unknown keys.
- `no-dream.json`: the day marker, `{"noDreamDate":"YYYY-MM-DD"}` (the latest day marked done; the name and key are legacy). It is written when a new note is first stored and when an empty launch note is left. Fails open: missing, empty, corrupt or wrong shape reads as no marker. The app never deletes it.
- Legacy, read-only (section 7): `dreams.json`, `dreams.json.bak`, `journals.json`, `dreams/`.

**Save order** (`saveNote`, an upsert by id, index work serialized): validate the id and body and that every new recording is a file inside the cache directory (before touching anything); refuse with `NOTE_IN_TRASH` for a trashed note; an emptied note (blank body, no recordings) goes to Recently Deleted with its text kept; copy each new recording from the cache into `notes/` one at a time, never overwriting; then `commitIndex`: write `notes.json.tmp`, read it back and check it parses with the same count, copy a content-bearing current index to `.bak` (a failure does not block the save), move the temp file over `notes.json` with overwrite. If the move leaves the index missing or damaged, recovery reads the temp file, then the backup. The cache files are deleted after a successful save. An unparseable, non-empty index is never overwritten: saves throw `INDEX_UNREADABLE`, the list shows an unreadable message and no launch note opens.

**Where files are deleted.** There are five production `.delete(` sites (all five are literal `.delete(` lines in a grep of `src`; other `.delete(` hits there are test helpers and a `Map` in `NoteListScreen`, not file deletion): `discardRecording` in `recordingFiles.ts` (the cache file of an unsaved recording); in `notesStorage.ts`, `saveNote` twice (the `undoCopies` rollback of copies a failed save just made, and the cache source files after a successful save), `deleteAudioFiles` (stored audio of a note being deleted forever or of a discarded held voice note; never a legacy file or one another note still references) and `scrubCopy` (the fallback when a leftover index copy cannot be overwritten). `CLAUDE.md` has the full deletion rules; do not add a `.delete(` call without the user's approval.

## 4. Decisions made during development

Notes-model decisions only; the earlier dream/journal-app decisions went with that app.

- **Stack**: Expo (SDK 57) + TypeScript, ESLint + Prettier, Jest. Local-only storage; no backend. A development build is required: `expo-speech-recognition`, `react-native-gesture-handler`, `expo-audio` and others are native, so Expo Go cannot load the app.
- **On-device by default.** Transcription runs on the device; audio goes to Apple or Google only when the user turns on "Transcribe voice notes online" and this phone cannot transcribe the note itself. The old live-text feature is removed.
- **Hard cutover** (user-approved): the import is one-time. Anything an older build writes to `dreams.json` after the first import is not imported, and an older build does not know `notes.json`, so notes created in the new app are not visible to it. `src/app/noLegacyWriters.test.ts` proves that nothing reachable from `App.tsx` imports the old writers and that `dreams.json` is named only in `services/legacyImport.ts`.
- **Four routes**. Search was a fifth route by user approval (2026-10-18, "Search returns in 7c") and was replaced by inline search in `NotesRoute` on 2026-10-20 (fewer routes, no new approval needed). Opening a result pushes `Editor` over the list and leaving returns to the same search; `NotesRoute` closes the drawer whenever it loses focus.
- **Delete forever is a scrub**: audio first, then the note's text from `.bak` and `.tmp`, then the index entry (the commit). Row swipe Delete and the editor's Delete move to Recently Deleted without confirm or undo (by decision).

## 5. Accepted behaviours

- **Stale-list open.** Opening a note from a list that is out of date (the note was trashed elsewhere) opens the editor; its first save returns `NOTE_IN_TRASH`, the in-trash banner shows with Leave, and the text stays on screen. If the list's own copy already carries `deletedAt`, `openNote` instead refreshes and shows the alert "This note is in Recently Deleted." With one device and one writer neither can happen, because of the `refresh()` rule.
- **Hard cutover**: later writes by an older build are not imported, and the older build cannot see new notes (section 4).
- **Row Delete has no undo**, and the delete dialogs' voice-note wording does not say that a file shared with another note is kept.
- **Launch cap** opens a new note even if the settings have not loaded; with an unreadable index the list shows instead.
- **Leaving a blank note trashes it.** Leaving a stored note whose body is blank and that has no live voice note moves it to Recently Deleted (step 4 of `useNoteSession.leave`; this includes a blank imported note). The text is kept, so Restore brings it back.
- **Edits after `leave()` starts are dropped.** Once `leave()` begins, further edits are ignored (the `leaving` flag). If the save then fails, the editor stays open with the last state it had before leaving started, without those edits.
- **`trash()` and `leave()` treat cache recordings differently (ruled intended).** After `NOTE_IN_TRASH`, `trash()` discards the unsaved cache recordings (the user chose to delete, so nothing can reference them), while `leave()` keeps them (the user did not choose to delete and they may be the only copy; the files are harmless in the OS cache). Ruling: `reports/2026-10-18-lucid-chunk-7a-1/architect-7a-1-ruling.md`, item 5.
- **Disclosure**: the transcripts of discarded voice notes can remain in `notes.json.bak` until the next index commit (usually the next autosave).
- **Storage limits**: if a commit is killed and every recovery step also fails, the index can be lost. There is no restore-from-backup feature and it would need the user's approval. Killing the app mid-recording leaves a cache file (`useVoiceRecorder` has no unmount cleanup).
- **Downgrade**: an older build ignores `notes.json` and shows only its own data. Data is kept either way.

## 10. Gotchas

- Run `npm run check` (typecheck, lint, format check, tests) before calling anything done.
- In tests, native modules must be mocked. `expo-audio` is mocked per test file; `expo-file-system` uses `src/test/fakeFileSystem.ts` via `jest.mock('expo-file-system', () => jest.requireActual('../test/fakeFileSystem'))`. With React Native Testing Library v14, `render` and `fireEvent` are async: `await` them.
- Storage changes need careful tests with that faithful fake (it models async copy/move, no-overwrite and failure injection). It cannot show real-device `File.move` or `File.copy` overwrite behaviour.
- Use `SafeAreaView` from `react-native-safe-area-context`, not from `react-native`. The app is wrapped in `SafeAreaProvider` in `App.tsx`.
- Install packages with `npx expo install` and check Expo's versioned docs before touching Expo APIs (see `AGENTS.md`).
- Tags are only ever read through `inlineTags` / `scanTags`; do not add another tag parser.
- The user keeps an uncommitted edit to the `android` / `ios` scripts in `package.json` (`expo run:android` / `expo run:ios`) in their own checkout; it must not be committed or reverted.
- On Windows, the PowerShell tool sometimes reports exit code 255 for commands that actually succeeded. Read the output to confirm.

Note (list editing 5b): `ListControlsPanel` (props-only panel shown in place of the keyboard), `panelContentHeight` (`src/utils/panelHeight.ts`, provisional fallback heights 260 iOS / 250 Android and a 200pt to half-window clamp) and `useKeyboardInset().lastHeight` (last non-zero keyboard height, remembered per orientation at module level) are wired by chunk 5d (the screen computes the panel height; see section 6).
