## 7a state (notes model, after the cutover)

This section is current; the sections below still describe the older dream and journal app until chunk 8 rewrites them.

**What is mounted.** `App.tsx` mounts `AppFlowProvider` (`src/app/AppFlowProvider.tsx`) and `NotesNavigator` with the four approved routes: `Notes` (the list, with the drawer), `Editor`, `Settings` and `RecentlyDeleted` (a stub: title, back arrow, "Deleted notes will appear here."). The old Today, Log, Search and Add routes, their provider and shell are gone. The `EXPO_PUBLIC_EDITOR_SPIKE` harness still replaces the app in dev builds.

**Works in Jest (nothing here is device-verified):** the launch rule (cap `LAUNCH_CAP_MS`, 1000 ms), the note list and drawer views, the editor with autosave, pin and delete in the editor's "..." menu, voice notes in notes, the import of earlier notes with its migration lines, and Settings ("Open a new note on launch", "When off, the app opens to the note list.", back label "Back to notes"; online transcription row unchanged).

**Import is a hard cutover.** `migrateLegacyDreams` runs at provider mount, inside the launch gate, on every launch (single-flight; a marker `migrated.json` makes later runs a no-op). It only reads `dreams.json`, `dreams.json.bak` and `dreams/`; it never writes or deletes them. Anything an older build writes to `dreams.json` after the first import is not imported. `src/app/noLegacyWriters.test.ts` proves that nothing reachable from `App.tsx` imports the old writers and that `dreams.json` is named only in `services/legacyImport.ts`. An older build does not know `notes.json`, so notes created in the new app are not visible to it.

**Accepted behaviour: a stale list.** Opening a note from a list that is out of date (the note was trashed elsewhere) opens the editor; its first save returns `NOTE_IN_TRASH` and the "in trash" banner shows with Leave, and the text stays on screen. This cannot happen with one device and one writer because every trash path goes through the provider, which calls `notes.refresh()`.

**Rule for 7b.** Every trash, restore or empty action from the list or the Recently Deleted screen must end with `notes.refresh()` before the UI re-renders. This is what keeps the stale-list case unreachable.

**Not done in 7a:** Search (7c), resume on a new day (7c), swipe pin/delete on rows and the real Recently Deleted screen (7b), the full docs rewrite and removal of the old code (chunk 8).

**Device checks still open (all of 7a):** cold launch into a new note and into the list; launch with a large legacy library (cap and the "Bringing in your earlier notes..." line); the migration lines; editor keyboard, caret and drawer gestures on iOS and Android; Android back (drawer, editor, Settings); the iOS swipe-back on Settings; voice notes in the editor; the Settings switch persisting across launches.

## 7b state (trash, restore, delete forever, row swipe)

Built in 7b-1 to 7b-3 and mounted: the real Recently Deleted screen (`src/screens/RecentlyDeletedScreen.tsx`, replacing the 7a stub; it keeps `RECENTLY_DELETED_COPY`), `DeletedNoteRow`, `deletedRow` / `noteHasDeletableAudio`, the two confirm dialogs (`src/utils/confirmForever.ts`, copy in `CONFIRM_FOREVER_COPY`) and the list's row swipe (`SwipeNoteRow`). Nothing here is verified on a device (iOS untested).

- **Where the logic is.** `AppFlowProvider` owns `restoreNote`, `requestDeleteForever`, `requestEmptyTrash`, `pinNote` and `trashNote`, the `trashBusy` guard (a ref plus state, held from the first tap through the confirm and the operation, and refused while a note is open, a leave is running or the index is unreadable), and `trashNotice` / `clearTrashNotice`. Wording is in `TRASH_COPY` (exported from the provider). The routes only pass these through; `RecentlyDeletedRoute` clears the notice on blur and unmount.
- **Deletion allow-list.** Only the provider calls `deleteForever` and `emptyTrash`, and only after the dialog's Delete forever / Empty button. `src/app/trashActions.audit.test.ts` pins this and that no screen, component or route imports a write function from `notesStorage`. Every action goes through the `useNotes` wrappers, which refresh the list after every outcome.
- **Behaviour.** Row swipe Delete moves the note to Recently Deleted at once (no confirm, no undo). Restore keeps the user on Recently Deleted with a `Restored "title".` line and a screen-reader "Restored"; the note is not opened and keeps its old position in the list. The Empty dialog mentions voice notes when any trashed note has deletable (non-legacy) audio. An Empty that reports 0 deleted with no failed id is treated as a failure.
- **Cleanups.** `NoteListScreen` memoizes `extraData` and the content style (a re-render test pins it); the swipe screen test wraps its fake `open()` calls in `act`.
- **Device checks still open (7b):** the real `Swipeable` inside the list on both platforms (open, scroll, open another, open a note), the left-edge drawer swipe against an open row and Android gesture navigation, VoiceOver and TalkBack custom actions on rows, restore of a note with a voice note, Delete forever and Empty with real audio files (and a legacy-imported note: `dreams/` audio must stay), the "Restored" announcement.
- **Known gaps:** no undo for row Delete (by decision); the delete dialog's voice-note wording does not say a file shared with another note is kept.

   - **Inline tags** (`src/utils/inlineTags.ts`, `TaggedBodyInput`, `TagSuggestionBar`, `src/utils/tagSuggestions.ts`): tags live in the body as `#tag` words and the page has no tag row or `TagInput`. A tag is `#` at the start of the text or after whitespace or one of `( [ { " '`, then 1 to 40 characters (code points) that are not whitespace or a terminator (`.,;:!?()[]{}<>"'/\|@#$%^&*+=~` and curly quotes and the ellipsis); trailing `-` and `_` are trimmed, a run of only digits is not a tag, and a longer run is not a tag at all. On save `saveDream` receives `tags: inlineTags(body)` (lowercase, de-duplicated, in order of first appearance) and the body unchanged as `transcript`, so the stored `tags` array stays the source for the logs, filters and Search. While typing, `TaggedBodyInput` highlights each tag by nesting `<Text>` runs inside the input; it has no `value` prop (React Native forbids `value` with children), so typing never remounts it but a programmatic change to the body (undo, redo, the "#" button, a suggestion tap) remounts it with the cursor restored. The "#" toolbar button inserts a `#` at the cursor (or the end of the body), adding a space first when the `#` would not parse. The suggestion bar sits above the toolbar while the body has focus and the cursor is in a `#word`: it offers the stored tags (`tagsByUse` over the library, most used first, converted to inline form) plus the tags already typed elsewhere in the entry (the word under the cursor left out), prefix matches before substring matches, at most 8 (`suggestTags`); tapping one completes the word (`#tag` plus a space) as one undo step. A word nothing matches shows no bar, and a new tag needs no action. When an existing entry is opened (an edit or a reopened draft) its stored tags that the body lacks are appended as a trailing line of `#tag` tokens (`materializeTags`, `entrySessionFromDream`); that addition is one undo step (the session's `materializedFrom` seeds the history) and counts into the edit baseline, so an edit that only opens does not look changed. A stored tag that cannot be one token is converted: whitespace and terminator characters become `-` ("bad dream" becomes `#bad-dream`, "v1.2" becomes `#v1-2`); a tag that is then empty, only digits or over 40 characters is not added, and a later save, which derives tags from the body only, drops it from the stored `tags`. Tag changes are made by typing, so deleting a tag word removes the tag on the next save.
   - **Undo / redo** (`useEntryHistory`): one stack for body typing (grouped after a 500 ms pause, on blur and before any other action; tags are body text, so typing them is covered, and the "#" button, a suggestion tap and the tags added on open are each their own step) and for closing a voice card (each close step names its recording, so undo brings back that one); not the title or journal. Capped at 100 steps; any new action clears redo; a save ends the history; a newly recorded note is not undoable. Both buttons are off while recording or saving.
   - **Leaving** (back arrow and Android back, one rule in `backFromAdd` in `App.tsx`): an empty new page just closes; a new entry or draft with anything on it (title, body text (tags are part of it), a visible recording, or a stored recording that was closed) asks "Save a draft?" / "Keep what you wrote to finish later, or discard it." with Save draft / Discard / Keep writing (nothing is stored until a choice is made; Save draft needs nothing else, and an empty draft is never created); an edit with changes asks "Discard changes?" - **Resume on a new day** (`useToday`, `src/hooks/useToday.ts`): returns `{ todayKey, resumeNewDayToken }`. `todayKey` is the local date, refreshed on AppState `active` and by one timeout to the next local midnight plus 1 s (`msUntilNextDay`, built from date parts so DST days are right), cleared when the app leaves the foreground and on unmount; no polling. `resumeNewDayToken` starts at 0 and goes up by one each time the app returns to the foreground on a different day than it left on (several days away count once; a same-day return, a repeated `active` event and a foreground midnight never bump it). `App.tsx` reacts to the token only: if the launch is done and the data is loaded, no session is open, no delete is running, the screen is not the add-entry page, auto-open is on, and nothing is done today, it opens the launch Dreams page (from any other screen, Settings included; `sessionOpen` is true whenever an entry is open on the page, so a half-written entry is never replaced). Each token is consumed once, so a resume that was blocked mid-flow does not try again that day. Today re-filters on a new day but never navigates by itself.
- **No dream marker** (`src/services/dayMarker.ts`, `src/hooks/useDayMarker.ts`): `Paths.document/no-dream.json` = `{"noDreamDate":"YYYY-MM-DD"}`, the latest skipped date only. It sits outside `dreams/` and the dream index, so saving, deleting and repairing dreams never touch it. Fail open: missing, zero-length, corrupt, wrong shape or a bad date reads as no marker (so the Dreams page opens). `markNoDream` updates state first and then writes; a failed write is swallowed (the value stays for the session); a slow read never overwrites a newer mark. **The app never deletes it**: a stale date is ignored and overwritten on the next skip. "Done today" is derived from the library and the marker, so deleting today's only finished dream re-opens capture on the next launch.
- **Settings** (`SettingsScreen`, `src/services/settingsStorage.ts`, `src/hooks/useSettings.ts`): header "Settings" with a back arrow ("Back to Today"), one `Switch` row "Open dream capture on launch" (default on) with the line "When off, the app opens to Today." `Paths.document/settings.json` = `{"autoOpenDreamCapture": true}`. Each key is validated on its own; missing, zero-length, corrupt, wrong shape or non-boolean falls back to on, so a damaged file never silences the prompt. Writes are read-modify-write, one at a time, keep unknown keys, swallow failures and never delete the file. The setter updates state at once; the toggle applies immediately and has no unsaved state. Off means launch always opens Today and resume changes nothing; "No dream" and "New dream" are unaffected.
- **Privacy**: the only new data is the latest skipped date and one boolean, in two small files on the device. Nothing leaves the phone.

Try again.", an unreadable-store message, or `Could not remove "<name>"` when only the registry write failed (journal kept, now empty). Refused with an alert if the index is unreadable; refused if an entry session is open in that journal or another delete is running. Dreams and Life cannot be renamed or deleted (`isBuiltInJournal` guards at every layer).
    - **Storage** (`src/services/journalStorage.ts`): `Paths.document/journals.json` = `{"version":1,"journals":[{"id","name","kind","createdAt"}]}`, custom journals only (ids `j_<base36>`, `kind` always `'journal'`, never a built-in id). **Data model** (`Dream`): `id`, optional `journalId` (absent means Dreams; see below), `createdAt` (ISO, when first stored; a draft counts), `durationMs` (0 when there is no audio; the first recording's length), optional `audioFileName` (the first recording's file; absent means no audio), optional `recordings` (`{ fileName, durationMs, waveform? }[]`, see below), `title` (empty only for drafts, old dreams and Life entries), optional `emotion`, `tags[]` (derived on save from the `#tag` words in the transcript), optional `transcript` (final edited text, trimmed, omitted when blank; tags are written in it as `#tag`), optional `status: 'draft'` (absent means finished). Emotion is one optional string of lowercase emotions joined with ", ", shown as chips with a capital first letter; emotions are no longer entered on the add-entry page (see item 1), and stored ones are kept and shown. Older dreams may hold free text in other cases; it is split on commas and semicolons only (never spaces) and matched case-insensitively.

**Journals in the data**: one shared index holds every journal's records. A record's optional `journalId` (`'dreams'`, `'life'` or a custom `j_...` id; an open string) says where it lives; a record without one is a Dreams entry, so there is no migration and old data is untouched. Always read it through `journalOf(record)`, never `record.journalId`. A new save stamps the journal (`saveDream` takes `journalId`, on create only, and `requireTitle`, default true; Life passes false); an edit never changes it. An id this version does not know is kept in storage and hidden from both logs and from Search. Delete, safety copies and repair are journal-agnostic (by id). Known limit (downgrade, accepted): a build from before journals existed shows Life and custom-journal entries as dreams; a build that knows only Dreams and Life hides custom-journal entries. Data is preserved either way.

**Recordings in the data**: an entry's voice recordings are the additive `recordings` list (`{ fileName, durationMs, waveform? }`), which is the truth when present and non-empty; there is no cap. `saveDream` also mirrors the FIRST recording into the legacy `audioFileName` / `durationMs` / `waveform` fields (removing them when the list is empty) so an older build still plays one recording. Only `saveDream` writes the mirror; read recordings only through `recordingsOf`, which falls back to the legacy fields for an entry with no `recordings` and drops unusable items. A legacy entry is converted lazily, the first time a save adds or removes one of its recordings; an untouched one is never rewritten. Downgrade: a build from before multiple recordings shows and plays only the first recording; if it deletes the entry it removes only that file, so the other recording files stay in `dreams/` unreferenced (orphans). Data is kept.

**Storage layout**: everything is under `Paths.document`. Two small files sit beside the dream data and are not part of it: `no-dream.json` (the latest skipped date) and `settings.json` (the launch toggle); see item 10. The app never deletes either, and the dream save, delete and repair code never touches them. `dreams.json` is the index. `dreams.json.bak` is a best-effort copy of the previous index, made before a write only when the current index is non-empty (a failed copy does not block saving). `dreams.corrupt-<timestamp>.json` is a copy of an unparseable index, made at most once per app session. Audio is in `dreams/` as `<id>.m4a`, or `<id>-<k>.m4a` if that name was taken. Only the audio **file name** is stored, never a full path, because the document directory path can change between app updates on iOS; always resolve audio through `recordingsOf(dream)` and `recordingUri(recording)` (`dreamAudioUri` gives the first recording's URI), never `audioFileName` directly. Dreams saved before titles/tags existed load with `title: ''` and `tags: []`.

**Save order** (`saveDream`, an upsert by id; writes run one at a time): validate the title (only for a finished dream), check that every name in `removeRecordings` belongs to the entry (else it throws before anything changes), copy each new recording (`addRecordings`) from the cache into `dreams/` one at a time (never overwriting, under `<id>.m4a`, `<id>-<k>.m4a` if taken), back up the index, write the index, then (if recordings were removed) rewrite `dreams.json.bak` from the new index and delete the removed files, and only then delete the cache files. If the index write fails, the copies this save made are removed and the index is repaired from the in-memory pre-save list first, then from `.bak`; an intact index is never touched. A zero-length `dreams.json` counts as missing (a non-empty `.bak` is then the base). An unparseable non-empty index is never overwritten: saving throws `INDEX_UNREADABLE`, the list shows "Your saved dreams could not be read. Your recordings are safe.", and saving stays refused until a restore feature exists. On update, `undefined` for emotion or transcript keeps the stored value and `''` clears it.

**Delete order** (`deleteDream(id)`, a finished or any stored dream by id; serialized with saves; throws on any failure; "scrub first, commit last"): (1) read the index; an unparseable one throws `INDEX_UNREADABLE` and nothing is touched; an unknown id is a no-op. (2) Check the audio targets before touching anything (`deletableAudioFiles`): each of the dream's recordings, by a plain file name that resolves inside `dreams/` and is not referenced by any recording of another dream. (3) Classify the safety copies `dreams.corrupt-<digits>.json` (documents folder, files only) read-only: Tier 0 does not mention the dream and is left untouched; Tier 1 mentions it and holds only dreams that are in the live index (a pure duplicate) and is deleted; anything else (holds a dream missing from the live index, or cannot be read or validated) blocks the delete (`isSafetyCopyBlockedError`) with nothing changed. Copies are never rewritten. Classification uses a strict JSON-prefix validator that tolerates trailing NULs and a BOM. (4) Rewrite `dreams.json.bak` without the dream (`[]` if empty, never a zero-length file; if the rewrite fails the `.bak` is deleted; if both fail the delete aborts). (5) Delete the audio files just before the index write (a missing file counts as success). (6) Write the index without the dream: this write is the commit. If it fails, the index is repaired with the same helper `saveDream` uses (memory first, then `.bak`) and the error is rethrown; the dream stays listed. Everything before step 6 can be repeated safely, so a retry converges. The app never unlists a dream while its audio or safety copies remain.

**Recording flow detail**: the recorder writes to the cache directory. Nothing is stored permanently until the entry is saved (the check, or Save draft on the leave prompt). Discarding a recording or leaving the page with Discard deletes only the cache files of recordings that were never saved; a stored recording is deleted only by `saveDream` with `removeRecordings` (or `removeAudio`, which means all of the entry's stored recordings). Files are deleted in only these cases (full wording in `CLAUDE.md`): `saveDream`'s own rollback of the copies that same save just made, `deleteDream` (see Delete order), the cache files of recordings that were never saved, a custom journal's delete (a loop of `deleteDream`), and `saveDream` with `removeRecordings` (or `removeAudio`) for the one entry the user chose to remove recordings from (the index is written without them first, then `dreams.json.bak` is rewritten from the new index and the files are deleted, never one that another record or a kept recording still references; the entry stays). Nothing else.

## Decisions made during development

- **Stack**: Expo (SDK 57) + TypeScript, ESLint + Prettier, Jest. Local-only storage; no backend.
- **On-device only.** Transcription runs on the device; no audio or text is sent anywhere. The old live text used `expo-speech-recognition` with the on-device request (the airplane-mode check on Android passed); that live-text code is removed. The `expo-speech-recognition` dependency, its `app.json` plugin and the permission strings stay, because file transcription after recording (A4) will use it.
- **A development build is required.** `expo-speech-recognition` (kept for A4) has native code, so Expo Go cannot load the app (the whole bundle fails to load). `expo-dev-client`, `expo-asset` and `expo-splash-screen` are installed and `expo` is on `~57.0.27`.
- **Voice is an attachment** (user, 2026-10-11): the add-entry page replaced the voice-first Capture screen. Each recording is a card above the title; the body is typed text. Transcribing a recording into the body after it stops is planned (A4) and not built; there is no live text.
- **Pause design** (retired): the old Capture screen paused the recorder first and stopped live recognition while paused. The add-entry page has no pause and no live text; `docs/spike-live-transcription.md` is the history of that spike.
- **Flow** (user, 2026-10-11): one add-entry page (title, body with inline `#tags`, optional voice recordings) replaced Capture, Read it back and Review. Nothing is stored permanently until the user saves (the check) or chooses Save draft on the leave prompt. Drafts are real dreams with `status: 'draft'`. Emotion was dropped from the page (stored values stay). Closing a voice card is undoable and applies on save. Several recordings per entry (no cap), and tags typed in the body as `#tag` instead of a tag row (user, 2026-10-11). The launch opens this page for Dreams, and backing out of it while empty counts as No dream.
- **Emotion** stays free text entries the user creates with a free-text input (never a fixed list or rating); quick-pick chips come from words used before. Tag suggestions come from tags used before and tags already in the entry being written (`suggestTags`). Nothing is derived from the content of a dream beyond the `#tag` words the user typed.
- **Storage safety**: copy-then-write-then-delete, a best-effort `.bak`, no overwrite of an unreadable index, one write at a time (decisions logged in the Steward repo).

**Accepted gaps**

- Storage: the index write is not atomic. A kill mid-write can leave an empty or partial index; if every repair step also fails, the whole index can be lost. `.bak` is copied non-atomically and is not strictly the last known good. **A restore-from-backup feature is not built and needs the user's approval.**
- The Dream log row accessibility labels read long dates.
- Delete (finished dreams) known gaps:
  - After a crash or an index-write failure right after the audio is deleted, the dream stays listed with a missing (silent) recording; text is intact and a retry finishes the delete.
  - A safety copy holding only a fragment of the deleted dream, cut before its id or audio name, is not detected and stays (read-only detection limit). Multi-point damage that leaves a copy valid JSON cannot be detected either.
  - A delete is blocked when a safety copy cannot be proven safe, and there is no in-app way to resolve it yet (needs the future restore-from-backup).
  - There is no missing-audio state in the player.
  - OS-level device backups and orphan audio from failed saves are out of scope.

## 7c resume

- Resume on a new day is wired in `src/app/AppFlowProvider.tsx`. `useToday` raises `resumeNewDayToken` when the app returns on a different day; one effect consumes each new token (always, so a blocked resume is never retried later that day) and, if `shouldResumeNewDay` (`src/utils/noteResume.ts`) allows it, opens the launch note and pushes `Editor` over the current screen. Leaving returns to that screen. An empty resumed note marks the day done through the existing `finishLeave`.
