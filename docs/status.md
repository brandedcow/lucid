## What works today

The add-entry page, Dream log and Dream entry are built and covered by tests, but **mostly not yet verified on a physical device** (see Gaps):

1. **Add-entry page** (`AddEntryScreen` for the layout, `AddEntryWithVoice` for the voice parts; session in `useEntrySession`). One page creates and edits every entry (a new entry, a reopened draft, an edit of a finished entry), in any journal. It replaced the old Capture, Read it back and Review screens. Layout, top to bottom: a top bar with a back arrow, the **journal pill** (a dropdown of the journals, accessibility label "Journal: <name>") and the **check** (label "Save dream" / "Save entry"); the date line ("Sunday, October 6", or the entry's stored date); the **voice attachment card** (only when there is a recording, above the title); the title field ("Title..."); the body field ("Start writing...", stored as the entry's `transcript`); the tag row (`TagInput`, "Add a tag...", with suggestions from tags used before); and at the bottom the **toolbar** (`EntryToolbar`: Undo, Redo, mic "Record voice note", "#" "Add tags"), inside the `KeyboardAvoidingView` so it rides above the keyboard on iOS and sits above the bottom inset when the keyboard is closed. There is no emotion field: it was dropped from the page, stored values stay (an edit passes the stored emotion back unchanged, and it still shows on the entry and in the logs). There is no separate "No dream" button.
   - **Journal picker** (`JournalPicker.tsx`: `JournalPill`, `JournalMenu`, an in-screen overlay, not a Modal): lists the journals (the parent leaves out a journal being deleted); Android back closes it first. It is live only for a new entry that has never been saved; a reopened draft, an edit, and an entry once a save created it show a plain label with no chevron (`entryJournalLocked`). The check's label and whether a title is needed (Dreams yes, other kinds no) follow the picked journal live. A new entry starts in the journal chosen from the "+" sheet or the log it was started from, or Dreams on launch.
   - **The check** saves a finished entry. It is off while a save is in flight, while a recording runs, and for a journal that needs a title until there is one. With no changes an edit just returns to the entry.
   - **Tag row**: hidden until it has content or the user taps "#"; "#" shows it and focuses the tag input, and taps again to hide it only while it is empty. Once it has had content in the session it stays open (latched) so removing the last tag or clearing the text never makes it vanish mid-edit. Tag text typed but not yet confirmed is saved as a tag too.
   - **Undo / redo** (`useEntryHistory`): one stack for body typing (grouped after a 500 ms pause, on blur and before any other action) and for closing the voice card; not the title, tags or journal. Capped at 100 steps; any new action clears redo; a save ends the history; a newly recorded note is not undoable and drops earlier close steps. Both buttons are off while recording or saving.
   - **Leaving** (back arrow and Android back, one rule in `backFromAdd` in `App.tsx`): an empty new page just closes; a new entry or draft with anything on it (title, body, a tag or tag text, a visible recording, or a stored recording that was closed) asks "Save a draft?" / "Keep what you wrote to finish later, or discard it." with Save draft / Discard / Keep writing (nothing is stored until a choice is made; Save draft needs nothing else, and an empty draft is never created); an edit with changes asks "Discard changes?" (Keep editing / Discard); an edit without changes returns to the entry. While a recording runs, back asks "Discard this recording?" first (see below), then the usual prompt. Back does nothing while a save is in flight.
   - **Launch behavior** (decided 2026-10-11): the launch rule, the auto-open setting and the resume jump on a new day all open this page for Dreams (a new entry in the Dreams journal, origin `new`, `launchPage` and `flowReturn: 'today'` in `App.tsx`). Backing out of an EMPTY launch page counts as No dream (marker written, Today, the page does not come back that day; no confirmation); with content it uses the leave prompt above and is not No dream; a launch page switched to another journal and backed out empty is not No dream either. Saving or saving a draft from it goes to Today.
   - **Not built / pending**: transcribing a recording into the body after it stops (chunk A4, waiting for the device spike A0). Until then a recording adds the audio card only; there is no live text and no transcript from voice, and the body is whatever the user types.
2. **Voice recording on the page** (`RecordingPanel`, `VoiceAttachmentCard`, `useDreamRecorder`, `useRecordingPlayback`, `src/utils/waveform.ts`). The mic in the toolbar starts recording (`expo-audio`) in a panel above the title: red dot, elapsed time, a stop button ("Stop recording"); no pause. The recorder's level is sampled every 100 ms and reduced to 56 peaks (`downsamplePeaks`). On stop the recording becomes the entry's attachment: the **card** has play/pause, a waveform that fills left to right as playback advances (a plain progress bar for an entry with no stored waveform), the length, and a close button ("Remove recording"). One recording per entry; the mic is off while one is shown. A new recording lives in the cache until the entry is saved. `waveform?: number[]` is an optional additive field on a stored entry (up to 128 values between 0 and 1; an invalid one is ignored, old entries have none). Mic permission denied shows "Microphone access needed" with the journal's message and no recording starts. Leaving while recording asks "Discard this recording?" / "Your recording will be deleted." (Keep recording / Discard): Discard stops the recorder, deletes the unsaved cache file, then carries on leaving (so an empty launch page counts as No dream, and a page with text asks its usual prompt). If the recorder cannot stop, "Could not finish recording" shows and the user stays.
3. **Closing the card and removal of stored audio**: closing the card (new or stored recording) only marks it removed in the session; it can be undone (and redone). Nothing persisted is deleted until the entry is saved. A closed new recording's cache file is deleted after a successful save or when the page is left (case 3 of the deletion rules); a closed STORED recording on an entry or draft is removed by the save that follows (the check, or Save draft from the leave prompt): `saveDream` with `removeAudio: true` writes the index without the audio, then deletes that file and rewrites `dreams.json.bak` (deletion case 5 in `CLAUDE.md`), keeping the entry itself, its text and its date. Leaving without saving forgets the mark and deletes nothing. Closing then recording again replaces the stored recording on save.
4. **Dream log** (`DreamLogScreen`): header "Dreams" with a search icon. Month sections (month in capitals, the year added when not the current year, "EARLIER" for a missing or invalid date). Tag chips: "All · N" and "tag · count" (the 20 most-used tags, selected tags always shown), multi-select; a dream must have ALL selected tags. Search (the icon replaces the title with a field and Cancel; the field has a clear (×) button once something is typed, and the "New dream" button is hidden while search is open) matches every typed word against title, transcript, emotion and tags (lowercased, accents stripped where the engine supports it; local text matching only) and combines with the tag filter. Rows: weekday and day, title (a short date when a finished dream has no title, "Untitled dream" when the date is missing or invalid), a 2-line transcript preview, emotion and tag chips (at most 4 chips in all, of which at most 2 are emotions, plus a "+N" overflow chip); no play button. **Rows, drafts included, swipe left to reveal a red "Delete"** (legacy `Swipeable` from `react-native-gesture-handler`; the revealed action is a 44pt button); tapping it shows the same "Delete this dream?" Keep / Delete confirmation as the entry. Every row also exposes an accessibility custom action "Delete" (swiping is unreachable with VoiceOver/TalkBack). A draft's delete confirmation and storage path are the same as a finished dream's (`deleteDream` removes its audio too). One row is open at a time (it closes on scroll and when another row or a dream is opened). Notes-style in-flight: only the row being deleted is dimmed and untappable, and swiping is disabled on all rows until it finishes; browsing, search, tag filters, opening other dreams and Android back stay free. A delete from the log does not navigate. Drafts appear inline by date as an outlined card (no chevron): title "Untitled dream" (or the title), with " · m:ss" when it has audio, and the sub-line "Draft · <date>" (short date such as "Oct 4", with the year when not the current year; "Draft" in red, the date in the muted color; just "Draft" when the date is invalid); its accessibility label is "Draft: <title>. <long date>. Tap to finish"; tapping reopens it on the add-entry page. The search field has a minimum height, line height and vertical padding so its placeholder is not clipped, and the clear (×) button is 42 high so it no longer makes the search pill grow. A "New dream" button (mic icon) opens the add-entry page. Empty ("No dreams yet."), no-results (with Clear) and unreadable-index states. The filter, search and scroll offset live in `useLogView` in `App.tsx`; the offset is restored once when the log is shown again.
5. **Dream entry** (`DreamDetailScreen`, finished dreams only): back and a top-right **"..." More options menu** (`OverflowMenu`, an in-screen overlay, not a `Modal`; closes on backdrop tap, on picking an item, and on Android back) holding Edit and a red Delete; a centered header date ("Dream · Sunday, October 4", "Life · …" for Life, the journal name alone with no date; same format as the add-entry page's date line, no time); the title (an untitled Dream still shows its short date as the heading, which repeats the header; an untitled Life entry has no heading); all emotion and tag chips; a compact audio player when the dream has audio; the transcript in paragraphs, or "No text yet". Edit opens the add-entry page for that dream (see item 1): the check saves the changes and returns to the entry, with no changes it just returns, back with changes asks "Discard changes?". Delete is the second menu item (finished dreams only; the menu item is absent when the screen gets no `onDelete`; disabled while this delete runs and while another delete is in flight, `deleteBlocked`). It opens a native confirmation (shared copy in `src/utils/confirmDelete.ts`), "Delete this dream?" / "The recording and text will be permanently deleted. This can't be undone." (no audio: "The text will be permanently deleted. This can't be undone."), with Keep and Delete. On Delete the player is unmounted (releasing the audio) and `App` calls `useDreamLibrary.remove(id)`; while it runs the menu's Delete is disabled and back (arrow and Android hardware back) and Edit are ignored, like back during a save. On success the app goes to the Dream log (only for a delete started on the entry), keeping its filter, search and scroll. On failure an alert "Could not delete dream" shows and the entry stays, with a retry possible: "Your saved dreams could not be read. Nothing was deleted." (unreadable index), "A saved copy of your dreams is damaged, so this dream was not deleted. Nothing was changed." (a safety copy blocks the delete; user-approved wording, 2026-10-10) or "Please try again." (anything else). The screen never touches storage and shows no alerts of its own on failure. Not built: "Also tagged" and "See all".

On Android back, an open "..." menu closes first.

10. **Today, Settings and the launch rule** (user decisions 2026-10-10; Part 2 of the journals plan).

- **Today** (`TodayScreen`): header with a book icon top left (`BookIcon`, label "Open Journals"), the title "Today" and the date, and a gear top right (`GearIcon`, "Open Settings"; both in `src/components/TodayIcons.tsx`). The list is `entriesToday` (`src/utils/today.ts`): entries whose `createdAt` falls on today's local date (`localDateKey`, never `toISOString`), from every known journal, drafts included, newest first, flat; a record with a missing or invalid `createdAt` never shows. Each row is a `SwipeEntryRow` with `variant="today"` (the swipe-to-delete row extracted from the Dream log, with per-journal delete wording) wrapping a flat `TodayEntryRow` (`src/components/TodayEntryRow.tsx`): hairline above, uppercase label "DREAM · 6:22 AM" / "LIFE · 6:22 AM" (`entryNoun` in `journals.ts` and `formatTimeOfDay` in `format.ts`, time from `createdAt`), large serif title (none for an untitled Life entry), the FULL body split into paragraphs (never truncated), then `OutlinedChips` (`src/components/OutlinedChips.tsx`) with all emotions then tags, no "+N". A draft keeps the frame with a red "DRAFT" in the label, no body, and still shows chips; tapping it reopens it on the add-entry page. The list ends with a hairline (`endRule`). The default `card` variant of `SwipeEntryRow` and the logs are unchanged. A quiet "No dream today" line shows when the skip marker is today and no Dream entry or draft exists today; empty states "Nothing here yet today." / "Nothing else yet today." (with the skip line), and the unreadable-index message. A "+" floating button (`AddEntryMenu`, "Add entry", bottom right, 56pt `FAB_SIZE`) opens a bottom sheet (header "Add entry", `maxHeight` 70%, one row per journal of `BUILT_IN_JOURNALS` styled like the Journals home cards; an in-screen overlay, not a Modal, so the delete Alert still shows on iOS; appears and disappears without animation with Reduce Motion on); picking calls `onNewEntry(journalId)`, which `App.tsx` turns into `startCapture(id, 'today')`. The sheet closes on the backdrop, on Android back (it registers `BackHandler` only while open) and for good when a delete starts (`deletingId`). The sheet is a full-screen layer outside the `SafeAreaView`, with the bottom inset passed in; the list pads its bottom by `insets.bottom + spacing.md + FAB_SIZE + spacing.lg`. The sheet's `onNewJournal` adds the "New journal" row (item 11); the `footer` slot stays free. No search. All wording is `TODAY_COPY`.
- **Launch rule** (`launchScreen` in `today.ts`, run once in `App.tsx`): `screen` starts `null` (a blank background view) until the library, the No dream marker, the settings and the journals have all loaded; then `dayStatus` (a finished Dream created today; the skip date equals today; drafts and Life entries do not count) and the toggle pick the Dreams add-entry page (`'add'`: auto-open on and nothing done) or Today. A 1000 ms cap (`LAUNCH_CAP_MS`) opens the Dreams page if the data is not ready; late data then never moves the user (`launchResolved`). The launch page (`launchPage` in `App.tsx`, set with `entry.startNew('dreams')`) has no "No dream" button: its back arrow and Android back, while the page is empty and a Dreams new entry, count as No dream (marker written, Today, no confirmation); with content they ask "Save a draft?" and do not count. While recording, back asks "Discard this recording?" first; Discard stops the recorder, deletes the unsaved cache file, then leaves as above (an empty page then counts as No dream). If the recorder cannot stop, the "Could not finish recording" alert shows and the user stays.
- **Transitions**: saving or saving a draft from the launch page goes to Today. `flowReturn` (`'today' | 'log'`) says where the add-entry page (a new entry, or a reopened draft) returns after a save or on back: pages started from Today or the Journals home return to Today, pages started from a log return to that log. A Dream page from the Dream log shows a back arrow to the log. An entry opened from Today has `detailFrom: 'today'` (back, and a delete from the entry, return to Today). Journals home: back arrow and Android back to Today; Settings: back arrow and Android back to Today; Today: no arrow, Android back exits.
- **Resume on a new day** (`useToday`, `src/hooks/useToday.ts`): returns `{ todayKey, resumeNewDayToken }`. `todayKey` is the local date, refreshed on AppState `active` and by one timeout to the next local midnight plus 1 s (`msUntilNextDay`, built from date parts so DST days are right), cleared when the app leaves the foreground and on unmount; no polling. `resumeNewDayToken` starts at 0 and goes up by one each time the app returns to the foreground on a different day than it left on (several days away count once; a same-day return, a repeated `active` event and a foreground midnight never bump it). `App.tsx` reacts to the token only: if the launch is done and the data is loaded, no session is open, no delete is running, the screen is not the add-entry page, auto-open is on, and nothing is done today, it opens the launch Dreams page (from any other screen, Settings included; `sessionOpen` is true whenever an entry is open on the page, so a half-written entry is never replaced). Each token is consumed once, so a resume that was blocked mid-flow does not try again that day. Today re-filters on a new day but never navigates by itself.
- **No dream marker** (`src/services/dayMarker.ts`, `src/hooks/useDayMarker.ts`): `Paths.document/no-dream.json` = `{"noDreamDate":"YYYY-MM-DD"}`, the latest skipped date only. It sits outside `dreams/` and the dream index, so saving, deleting and repairing dreams never touch it. Fail open: missing, zero-length, corrupt, wrong shape or a bad date reads as no marker (so the Dreams page opens). `markNoDream` updates state first and then writes; a failed write is swallowed (the value stays for the session); a slow read never overwrites a newer mark. **The app never deletes it**: a stale date is ignored and overwritten on the next skip. "Done today" is derived from the library and the marker, so deleting today's only finished dream re-opens capture on the next launch.
- **Settings** (`SettingsScreen`, `src/services/settingsStorage.ts`, `src/hooks/useSettings.ts`): header "Settings" with a back arrow ("Back to Today"), one `Switch` row "Open dream capture on launch" (default on) with the line "When off, the app opens to Today." `Paths.document/settings.json` = `{"autoOpenDreamCapture": true}`. Each key is validated on its own; missing, zero-length, corrupt, wrong shape or non-boolean falls back to on, so a damaged file never silences the prompt. Writes are read-modify-write, one at a time, keep unknown keys, swallow failures and never delete the file. The setter updates state at once; the toggle applies immediately and has no unsaved state. Off means launch always opens Today and resume changes nothing; "No dream" and "New dream" are unaffected.
- **Privacy**: the only new data is the latest skipped date and one boolean, in two small files on the device. Nothing leaves the phone.

11. **Custom journals** (user decisions 2026-10-10 and 2026-10-11; Part 1b of the journals plan).
    - **Create**: the "+" sheet on Today (and on the Journals home, see below) has a "New journal" row below the journal rows (`AddEntryMenu` `onNewJournal`, wired in `TodayScreen`); it opens `NewJournalSheet` (`NEW_JOURNAL_COPY`: "New journal", "Create", "Cancel", placeholder "Journal name"), an in-screen overlay over Today. Name rules are `validateJournalName` in `src/utils/journalName.ts` (trimmed, inner whitespace collapsed, 1 to `JOURNAL_NAME_MAX` = 24 characters counted by code point, unique case-insensitively against ALL journals including Dreams and Life; the one being renamed is excluded via `excludeId`); problems show as the user types and Create is disabled while invalid. On submit `App.tsx` calls `journalRegistry.add(name)` and only then `showLog(created.id)`, so the empty log opens with "New entry"; a failed write rejects and the sheet stays open with a save-failed message.
    - **Add button on Journals home**: `JournalsScreen` takes optional `onNewEntry` / `onNewJournal` and shows the same `AddEntryMenu` FAB and sheet as Today (a row per journal plus "New journal"; the list pads its bottom for the button). `App.tsx` turns a pick into `startCapture(id, 'today')`, so Back, leave and after-save return to Today, not Journals home; "New journal" opens the name sheet over Journals home, and on create the empty log opens. The FAB is hidden while a name sheet (new or rename) is open (`nameSheetOpen`) and disabled while a journal delete runs; the sheet closes for good when a delete starts, as on Today.
    - **Behaviour**: a custom journal is `kind: 'journal'`, so it follows Life's rules (`titleRequired` false, no skip, `JOURNAL_COPY` wording, no icons or colors). `journalCopy(journal)` fills the name-bearing fields (log header, "<Name> · " date prefix, search label, empty state) from the name, cached per journal object in a `WeakMap`; Dreams and Life keep their hand-written strings. Creation order, no limit. Registry: `useJournals` (`src/hooks/useJournals.ts`) returns `{ journals, custom, loaded, add, rename, remove }` (built-ins first); state updates only after the file write succeeds, a late initial read never overwrites a change, and `loaded` joins the launch-rule gate.
    - **Rename**: on the Journals home a custom card swipes to reveal Rename then Delete (`SwipeActionRow`, the generic multi-action swipe row, `src/components/SwipeActionRow.tsx`; `SwipeEntryRow` builds on it; each action also a screen-reader custom action). Rename reuses `NewJournalSheet` with `title="Rename journal"`, `submitLabel="Save"`, `initialName` and `excludeId`; name only (id, kind and date stay). `canRenameJournal` refuses while a journal delete runs or its confirmation is up; an unchanged name closes without writing. The sheet closes if the screen changes or the journal vanishes.
    - **Delete**: swipe, Delete, then `confirmDeleteJournal` (`src/utils/confirmDelete.ts`): `Delete "<name>"?` with Keep / Delete and the entry count from `entriesFor` (drafts included; recordings mentioned only when some entry has audio; "no entries" wording for an empty journal); "This can't be undone." `deleteJournalFor` in `App.tsx` removes every entry (drafts included) with `useDreamLibrary.removeMany(ids)` (the existing `deleteDream` per id, one at a time, stops at the first failure, never throws, returns `{ deleted, remaining, failedId?, error? }`, one refresh at the end), then re-reads the stored entries, and only if none remain calls `journalRegistry.remove(id)` LAST, so entries are never left without their journal. While it runs (`deletingJournalId`) the card is greyed, inert and reads "Deleting..." with every card's swipe locked, and the journal's entries and its row in the Add sheet are hidden (`visibleRecords`, `visibleJournals`; the card count reads unfiltered records); a screen showing that journal (its log or an entry) goes back to the Journals home. Failure alerts (title `Could not delete "<name>"`): "Deleted N of M entries. K still remain. Try again.", an unreadable-store message, or `Could not remove "<name>"` when only the registry write failed (journal kept, now empty). Refused with an alert if the index is unreadable; refused if an entry session is open in that journal or another delete is running. Dreams and Life cannot be renamed or deleted (`isBuiltInJournal` guards at every layer).
    - **Storage** (`src/services/journalStorage.ts`): `Paths.document/journals.json` = `{"version":1,"journals":[{"id","name","kind","createdAt"}]}`, custom journals only (ids `j_<base36>`, `kind` always `'journal'`, never a built-in id). Reads fail open (missing, empty, unreadable, corrupt or wrong shape gives no custom journals; each entry is validated alone and bad ones are dropped in memory only; an interrupted write's `journals.tmp.json` is read when `journals.json` is missing or empty). Writes are serialized (read fresh each time, so none is lost), atomic (write the tmp file, then move over `journals.json`), keep unknown top-level keys and extra per-journal keys, and when the old content was damaged copy it once per session to `journals.corrupt-<n>.json` first. The last removal writes an empty list, never an empty file. **The app never deletes `journals.json`.** `addJournal` / `renameJournal` / `removeJournal` throw `JournalError` (`invalid-name`, `built-in`, `not-found`). Journal names stay on the device.
    - **Entries**: `journalId` is an open string; an id not in the registry is preserved in storage and hidden from the logs, Today and Search (and its row simply has no journal). Deleting a journal deletes its entries and audio by the normal `deleteDream` path (safety-copy rules included, so a blocked delete leaves the journal in place).
    - **Downgrade**: a build from before journals existed ignores `journalId`, so it shows custom-journal entries (and Life entries) as dreams; a build that knows Dreams and Life but not custom journals hides custom-journal entries. Data is preserved either way.
12. **Icon and splash**: a moon mark. `assets/icon.png` (full-bleed), `android-icon-foreground/monochrome/background.png`, `favicon.png` and `splash-icon.png`; source SVGs and generation notes are in `assets/icon-source/`. The `expo-splash-screen` plugin in `app.json` shows the splash on #0D1017 at width 200. They need a native rebuild to appear (see Repo and workflow state).

**Data model** (`Dream`): `id`, optional `journalId` (absent means Dreams; see below), `createdAt` (ISO, when first stored; a draft counts), `durationMs` (0 when there is no audio), optional `audioFileName` (absent means no audio), `title` (empty only for drafts, old dreams and Life entries), optional `emotion`, `tags[]`, optional `transcript` (final edited text, trimmed, omitted when blank), optional `status: 'draft'` (absent means finished). Emotion is one optional string of lowercase emotions joined with ", ", shown as chips with a capital first letter; emotions are no longer entered on the add-entry page (see item 1), and stored ones are kept and shown. Older dreams may hold free text in other cases; it is split on commas and semicolons only (never spaces) and matched case-insensitively.

**Journals in the data**: one shared index holds every journal's records. A record's optional `journalId` (`'dreams'`, `'life'` or a custom `j_...` id; an open string) says where it lives; a record without one is a Dreams entry, so there is no migration and old data is untouched. Always read it through `journalOf(record)`, never `record.journalId`. A new save stamps the journal (`saveDream` takes `journalId`, on create only, and `requireTitle`, default true; Life passes false); an edit never changes it. An id this version does not know is kept in storage and hidden from both logs and from Search. Delete, safety copies and repair are journal-agnostic (by id). Known limit (downgrade, accepted): a build from before journals existed shows Life and custom-journal entries as dreams; a build that knows only Dreams and Life hides custom-journal entries. Data is preserved either way.

**Storage layout**: everything is under `Paths.document`. Two small files sit beside the dream data and are not part of it: `no-dream.json` (the latest skipped date) and `settings.json` (the launch toggle); see item 10. The app never deletes either, and the dream save, delete and repair code never touches them. `dreams.json` is the index. `dreams.json.bak` is a best-effort copy of the previous index, made before a write only when the current index is non-empty (a failed copy does not block saving). `dreams.corrupt-<timestamp>.json` is a copy of an unparseable index, made at most once per app session. Audio is in `dreams/` as `<id>.m4a`, or `<id>-<k>.m4a` if that name was taken. Only the audio **file name** is stored, never a full path, because the document directory path can change between app updates on iOS; always resolve it through `audioFileName` / `dreamAudioUri`. Dreams saved before titles/tags existed load with `title: ''` and `tags: []`.

**Save order** (`saveDream`, an upsert by id; writes run one at a time): validate the title (only for a finished dream), copy the recording from the cache into `dreams/` (never overwriting), back up the index, write the index, and only then delete the cache file. If the index write fails, the copied audio is removed and the index is repaired from the in-memory pre-save list first, then from `.bak`; an intact index is never touched. A zero-length `dreams.json` counts as missing (a non-empty `.bak` is then the base). An unparseable non-empty index is never overwritten: saving throws `INDEX_UNREADABLE`, the list shows "Your saved dreams could not be read. Your recordings are safe.", and saving stays refused until a restore feature exists. On update, `undefined` for emotion or transcript keeps the stored value and `''` clears it.

**Delete order** (`deleteDream(id)`, a finished or any stored dream by id; serialized with saves; throws on any failure; "scrub first, commit last"): (1) read the index; an unparseable one throws `INDEX_UNREADABLE` and nothing is touched; an unknown id is a no-op. (2) Check the audio target before touching anything: a plain file name that resolves inside `dreams/` and is not referenced by another dream. (3) Classify the safety copies `dreams.corrupt-<digits>.json` (documents folder, files only) read-only: Tier 0 does not mention the dream and is left untouched; Tier 1 mentions it and holds only dreams that are in the live index (a pure duplicate) and is deleted; anything else (holds a dream missing from the live index, or cannot be read or validated) blocks the delete (`isSafetyCopyBlockedError`) with nothing changed. Copies are never rewritten. Classification uses a strict JSON-prefix validator that tolerates trailing NULs and a BOM. (4) Rewrite `dreams.json.bak` without the dream (`[]` if empty, never a zero-length file; if the rewrite fails the `.bak` is deleted; if both fail the delete aborts). (5) Delete the audio file just before the index write (a missing file counts as success). (6) Write the index without the dream: this write is the commit. If it fails, the index is repaired with the same helper `saveDream` uses (memory first, then `.bak`) and the error is rethrown; the dream stays listed. Everything before step 6 can be repeated safely, so a retry converges. The app never unlists a dream while its audio or safety copies remain.

**Recording flow detail**: the recorder writes to the cache directory. Nothing is stored permanently until the entry is saved (the check, or Save draft on the leave prompt). Discarding a recording or leaving the page with Discard deletes only the cache files of recordings that were never saved; a stored recording is deleted only by `removeAudio`. Files are deleted in only these cases (full wording in `CLAUDE.md`): `saveDream`'s own rollback of the copy that same save just made, `deleteDream` (see Delete order), the cache file of a recording that was never saved, a custom journal's delete (a loop of `deleteDream`), and `saveDream` with `removeAudio` for the one entry the user chose to remove the recording from (the index is written without the audio first, then the file is deleted and `dreams.json.bak` is rewritten from the new index; the entry stays). Nothing else.

## Decisions made during development

- **Stack**: Expo (SDK 57) + TypeScript, ESLint + Prettier, Jest. Local-only storage; no backend.
- **On-device only.** Transcription runs on the device; no audio or text is sent anywhere. The old live text used `expo-speech-recognition` with the on-device request (the airplane-mode check on Android passed); that live-text code is removed. The `expo-speech-recognition` dependency, its `app.json` plugin and the permission strings stay, because file transcription after recording (A4) will use it.
- **A development build is required.** `expo-speech-recognition` (kept for A4) has native code, so Expo Go cannot load the app (the whole bundle fails to load). `expo-dev-client`, `expo-asset` and `expo-splash-screen` are installed and `expo` is on `~57.0.27`.
- **Voice is an attachment** (user, 2026-10-11): the add-entry page replaced the voice-first Capture screen. A recording is a card above the title; the body is typed text. Transcribing a recording into the body after it stops is planned (A4) and not built; there is no live text.
- **Pause design** (retired): the old Capture screen paused the recorder first and stopped live recognition while paused. The add-entry page has no pause and no live text; `docs/spike-live-transcription.md` is the history of that spike.
- **Flow** (user, 2026-10-11): one add-entry page (title, body, optional voice recording, tags) replaced Capture, Read it back and Review. Nothing is stored permanently until the user saves (the check) or chooses Save draft on the leave prompt. Drafts are real dreams with `status: 'draft'`. Emotion was dropped from the page (stored values stay). Closing the voice card is undoable and applies on save. The launch opens this page for Dreams, and backing out of it while empty counts as No dream.
- **Emotion** stays free text entries the user creates with an input like the tag input (never a fixed list or rating); quick-pick chips come from words used before. Tag suggestions come only from tags used before. Nothing is derived from the content of a dream.
- **Storage safety**: copy-then-write-then-delete, a best-effort `.bak`, no overwrite of an unreadable index, one write at a time (decisions logged in the Steward repo).
- **System fonts for now.** The mockups use a display serif and a geometric sans; matching them would need bundled fonts.
- **Expo Router is NOT adopted.** `AGENTS.md` (from the Expo template) says to use it, but the app keeps the `App.tsx` state switch with `useEntrySession`. Do not add routes or another navigation library without asking.
- **"No dream"** is the label for the empty launch page counted as skipped (not "Skip"); it is no longer a button. **Title is required** to finish a dream (other journals: optional); tags are optional.
- **Dream log and entry** (user, 2026-10-06): the log was not a journal home then (superseded by the multiple-journals decision below: the Journals home now sits above the logs). Search covers title, transcript, emotion and tags, local text matching only. The tag filter is multi-select and a dream must have all selected tags. Edit opens the add-entry page; the check on an edited dream returns to its entry. The draft sub-line is "Draft · <date>" with "Draft" in red and the date muted (changed from "Draft · Not reviewed yet · Finish now"). No delete in this work; "Also tagged" and "See all" were removed from the entry (to revisit with AI suggestions later; AI features remain out of scope for v1). System fonts kept.
- **OS floor** (user, 2026-10-06): older phones can install the app; there is no install-time block. (The floor was set for live text, which is removed; file transcription (A4) will need its own OS check.)
- **Delete UX rework** (user, 2026-10-10): this supersedes the bottom red "Delete dream" button and the standalone Edit control on the entry. The entry has a top-right "..." menu with Edit and Delete. On the Dream log, swiping a finished row reveals Delete, and tapping it shows the same confirmation. In-flight behavior on the log is Notes-style (only the row being deleted is locked). Swipe uses `react-native-gesture-handler`'s legacy `Swipeable` (upstream-deprecated in favor of the Reanimated version; chosen to avoid adding Reanimated/worklets). Drafts stay non-deletable (superseded: drafts are now swipe-deletable too).
- **Delete for finished dreams** (user, 2026-10-10): permanent, no trash and no undo; a confirmation alert; drafts are deletable too since the journals validation fixes; safety copies never keep a deleted dream and never lose other dreams (a delete is blocked instead).
- **Multiple journals** (user, 2026-10-10): a journal is a container; the built-in ones are Dreams (existing dreams) and Life (the everyday entries); user-created journals were added in Part 1b (item 11). The Today page was built as Part 2 (see the next decision). No "Journals" link on dream capture: the Journals home is reached from a log's back arrow (now also from the book icon on Today). The Life header date line is "Life · <date>" (changed from date-only, user, same day); the Life title field is not autofocused. Cross-journal Search, the Life wording and the navigation above were approved. Wording changes come from the user's manual validation, not from questions to the user.
- **Today, Settings and the launch rule** (user, 2026-10-10): Today is the main hub and shows only today's entries from every journal. "Done today" means a finished Dream saved today or "No dream" chosen today (a draft does not count, Life entries do not); the app opens to Dream capture only when nothing is done and the toggle is on, else to Today. The skipped date is stored on the device (approved). A Settings page with one toggle, "Open dream capture on launch" (default on), reached from a gear on Today. The Journals home is reached from a book icon on Today (no "Journals" text link) and keeps a back arrow and Android back to Today; Android back on Today exits. Resume on a new day with nothing done jumps to Dream capture and honours the toggle. Dream capture from the Dream log has a back arrow and no "No dream". Wording was picked by the builders (copy in `TODAY_COPY`, the Settings strings); the user edits it during manual validation.
- **Audio is kept** alongside the entry's text when the user records; a recording the user closes is removed when they save (deletion case 5 in `CLAUDE.md`).

Android: after `expo-dev-client` was added, rebuild once locally (`npm run android`), then start Metro with `npm start`. iOS: build in the cloud with EAS as described in `docs/ios-dev-build.md`; it needs a paid Apple Developer account, which is pending (iOS untested).
- **New dependency `react-native-gesture-handler` (~2.32.0) is native: a dev-client rebuild is required** (Android `npm run android`; iOS a new EAS build) before the swipe works on a device. `ios/` and `android/` are generated output; never hand-edit them.
- The user keeps an uncommitted edit to the `android` / `ios` scripts in `package.json` (`expo run:android` / `expo run:ios`); it stays local and must not be committed or reverted.
- The app icon and moon splash are in `assets/` but appear only after a native rebuild: Android needs `npx expo prebuild --platform android --clean` then `npm run android`; iOS needs a new EAS build. Not set up yet: CI and any secrets/`.env` handling.
- A project hook (`.claude/hooks/format.js`) runs Prettier on files after Claude edits them, and `.claude/settings.json` denies force-pushes, remote-branch deletion, pushes to `main`, and reading `.env*` files; other `git push` calls still prompt. This is a best-effort guard (pattern matches can be bypassed); GitHub branch protection is the robust control.

## Gotchas

- Run `npm run check` (typecheck, lint, format check, tests) before calling anything done.
- In tests, native modules must be mocked. `expo-audio` is mocked per test file; `expo-file-system` uses `src/test/fakeFileSystem.ts` via `jest.mock('expo-file-system', () => jest.requireActual('../test/fakeFileSystem'))`. With React Native Testing Library v14, `render` and `fireEvent` are async: `await` them.
- Storage changes need careful tests with the faithful fake `src/test/fakeFileSystem.ts` (it models async copy/move, no-overwrite and failure injection).
- Use `SafeAreaView` from `react-native-safe-area-context`, not from `react-native` (deprecated). The app is wrapped in `SafeAreaProvider` in `App.tsx`.
- Install packages with `npx expo install`, and check Expo's versioned docs before touching Expo APIs (see `AGENTS.md`); Expo APIs change between SDKs.
- On Windows, the PowerShell tool sometimes reports exit code 255 for commands that actually succeeded (seen with some git and npm commands). Read the output to confirm.
