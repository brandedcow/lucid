Where the project stands, so anyone (human or agent) can pick it up. `docs/product.md` says what the app is; this file says what exists, what is unverified, and what to watch out for. Update it when you change the state of the project.

## 1. Where it stands

Lucid is a voice-first notes app: markdown notes with inline `#tags`, voice notes attached to a note, a note list with a drawer of smart views, Recently Deleted, search, and a one-time import of the earlier dreams and journals data. The notes-model work (chunks 1 to 8) is built and covered by Jest, and the old dream and journal code is deleted. **The user tried chunk 9 only (drawer with parallax, left-edge swipe, Today default, inline search with highlighting, Today = created or updated today) on the phone and accepted it on 2026-10-20 ("Tested the changes, accepted"; no per-check detail recorded). Everything else under "What works today" (launch and resume rule, editor, voice notes and transcription, import, trash and restore, row swipe, and anything outside chunk 9) has no recorded device result and is Jest only. The chunk-10 work (icons, sort menu, date header, Recently Deleted dropdown row) is not yet checked on a device.** The only per-check device results on record come from the retired live-text build (Android: audio quality fine, long text scrolls, airplane mode works, no beeps at restarts) and say nothing about the current app. iOS has never been run (the paid Apple Developer account is pending). The 6c editor spike items and the other device checks in section 6 remain open.

## 2. What works today

All of this is built, mounted from `App.tsx`, and tested in Jest. **The only device result on record for the current app is the user's acceptance of chunk 9 only (drawer with parallax, left-edge swipe, Today default, inline search with highlighting, Today = created or updated today) on 2026-10-20, with no per-check detail; everything else here, and the chunk-10 work, has no recorded device result and is Jest only.**

- **Launch and resume** (`src/app/AppFlowProvider.tsx`, `src/utils/noteLaunch.ts`, `src/utils/noteResume.ts`, `src/hooks/useToday.ts`). A cold start waits until the stores and the one-time import have loaded, then opens a new empty note on top of the list (setting on, day not settled, notes index readable) or shows the list. A cap of `LAUNCH_CAP_MS` (1000 ms) opens a new note anyway if the data is not ready, and late data never moves the user afterwards. Returning to the app on a different day raises `resumeNewDayToken`; one effect consumes each token once and, if `shouldResumeNewDay` allows it (launch decided, notes loaded and readable, setting on, day not settled, no open note, no running leave/delete/trash action, not already on the editor, navigation ready), pushes a new launch note over the current screen (the list, Settings or Recently Deleted; with search open on the list the search state is kept). Leaving it returns to that screen. An empty launch note marks the day done through the normal leave path. "Day settled" is derived from the notes and the day marker (section 3).
- **Note list, drawer and smart views** (`NoteListScreen`, `NotesDrawer`, `src/utils/noteViews.ts`, `noteViewLabels.ts`, `noteRow.ts`). The list shows Today by default (notes updated or created on the local day; one `DEFAULT_VIEW` constant in `AppFlowProvider`; pin and restore do not touch `updatedAt`, so they do not add a note to Today). The left drawer (opened by the header menu button or a left-edge swipe, `useDrawerGesture`; the page slides right and the drawer sits behind it, fading in with a slight slide, `useDrawerProgress`) has a dropdown of smart views (Today, All Notes, Todo, Untagged, Pinned), a list of tags with live-note counts, and Recently Deleted (with a count when above zero) as the last row of the dropdown only (the footer row was removed in chunk 11a), with icons on the views (`DrawerIcons`). The footer has a Settings gear (bottom left) and a tag sort button (bottom right) that opens `TagSortMenu` upward (A to Z by default, Most notes; `sortTags`); the choice is `tagSort` in `settings.json`. Today shows its date under the title (`formatDayKey(todayKey)`, `todayKey` from `AppFlowProvider`, so it rolls over with the Today filter at midnight); other views and searching show none. `NotesRoute` wires the date, `tagSort` and `setTagSort` from `useAppFlow().settings`; route tests use the real drawer and list. The view is session-only and starts at Today, and returns to Today if the selected tag disappears. The launch rule (`dayDone`) deliberately still counts notes created today, not edited today. Chunk 9 (drawer, edge swipe, Today default, Today = created or updated today) was accepted by the user on the phone on 2026-10-20, individual checks not recorded; the chunk-10 parts (icons, sort menu, date header, Recently Deleted dropdown row) are not yet checked on a device. Rows show title, preview, up to 3 tags (`MAX_ROW_TAGS`) with "+N", and a relative time. Rows swipe (`SwipeNoteRow`, built on the legacy `Swipeable` from `react-native-gesture-handler`) to Pin or Delete; Delete moves the note to Recently Deleted at once, with no confirm and no undo.
- **Editor, markdown and autosave** (`NoteEditorScreen`, `NoteEditorWithVoice`, `NoteBodyInput`, `useNoteEditor`, `useNoteSession`, `src/utils/markdownEdit.ts`, `markdownLines.ts`). One page creates and edits every note. The title is derived from the body (`noteTitle`). The body is a multiline `TextInput` with nested styled `<Text>` runs (`STYLE_LEVEL = 'full'`: sized headings, bold, italic, bullets, numbered lists, checkboxes, dimmed markers, strike-through on checked items; bodies over `STYLE_MAX_CHARS` = 20000 are not styled). Enter continues a list item and Enter on an empty item exits the list (detected by diffing the text, not by key events). The toolbar (`NoteToolbar`) has Undo, Redo (`useEntryHistory`), record a voice note, tags and a checkbox button acting on the caret's line (labels "Add checkbox", "Check item", "Uncheck item"). Tags are `#word`s typed in the body (`src/utils/inlineTags.ts`); `TagSuggestionBar` offers known tags while one is being typed. Autosave debounces at 1000 ms with a 10 s maximum wait (`useNoteSession`). The "..." menu (`OverflowMenu`) has Pin / Unpin and "Delete note". Leaving always goes through the provider's `leaveEditor`, which saves first; a failed save shows "Couldn't save your note" with Keep editing / Leave anyway and the text stays on screen. A note that is in Recently Deleted shows a banner and stops autosaving. The iOS edge-swipe back is handled by `useBackEdgePrompt`; the native swipe is off on `Editor`.
- **Voice notes and transcription** (`RecordingPanel`, `RecordingWaveform`, `VoiceNoteCarousel`, `VoiceAttachmentCard`, `VoiceNoteSheet`, `useVoiceRecorder`, `useRecordingPlayback`, `useAutoTranscribe`, `useRecordingTranscription`, `src/services/transcription.ts`). The toolbar mic opens the recording panel (no recorder or permission request until Start recording). A recording is a card above the body; tapping it opens the expanded sheet (seekable waveform, share, delete, transcript view). Closing a card is undoable. A new recording stays in the cache until the note is saved. New recordings are transcribed automatically, one at a time, on-device only (an automatic start never prompts and never uses the network); the text is kept on the recording as `voiceTranscript` and shown in the sheet, it is not inserted into the note body. The sheet also offers Transcribe when the route allows it. The "Transcribe voice notes online" setting (default off, fails closed) is the only thing that permits an online run (audio then goes to Apple or Google). One card plays at a time.
- **Recently Deleted, restore, delete forever** (`RecentlyDeletedScreen`, `DeletedNoteRow`, `src/utils/deletedRow.ts`, `confirmForever.ts`). Restore keeps the user on Recently Deleted with a `Restored "title".` line and a screen-reader "Restored"; the note is not opened. Delete forever and Empty each ask a confirm dialog (`CONFIRM_FOREVER_COPY`); the Empty dialog mentions voice notes when any trashed note has deletable (non-legacy) audio. Delete forever removes the note's own audio files, scrubs the note's text from `notes.json.bak` and `notes.json.tmp`, then removes the index entry; legacy audio in `dreams/` is never deleted, and `notes.corrupt-*` copies are left alone. An Empty that reports 0 deleted with no failed id is treated as a failure.
- **Search** (inline in `NotesRoute` in `src/navigation/notesRoutes.tsx`, `NoteSearchPanel` with `SearchHeader`, `src/utils/noteSearch.ts`, `noteHighlight.ts`, `SearchButton`). Search is a state of the `Notes` route, not a screen (the `Search` route was removed on 2026-10-20). The magnifier in the list header (hidden when the index is unreadable) turns the header into the search field (focused, a "Close search" arrow instead of the menu button) and draws the results over the list body; the list stays mounted underneath and is hidden from screen readers. Every word must appear in the note body (lowercased, accents folded where the engine supports it); a `#tag` term matches as a prefix of one of the note's tags; selected tag chips filter further; results are grouped by month under a "N notes found" line (a polite live region). Matches are highlighted in the title, the preview and the tag line (`NoteRow` with `noteRow(note, now, parsed)`); a word found only beyond the preview shows an excerpt with `…`. Recently Deleted notes are never searched. The query and chips are `NotesRoute` state, so they survive a note being opened over the list and are cleared when search closes (the arrow, Android back, or the drawer opening). The Android back handler is registered only while the route is focused and searching. The drawer drag is told `searching` and stays off; the "+" button still works. Results, the count and sections come from one `useMemo`; no timers or debounce. Accepted by the user on the phone on 2026-10-20 (inline search with highlighting; no further detail recorded).
- **Settings** (`SettingsScreen`, `settingsStorage`, `useSettings`). Two switches: "Open a new note on launch" (default on; helper line "When off, the app opens to the note list.") and "Transcribe voice notes online" (default off). Back label "Back to notes". The file is described in section 3.
- **Import of earlier notes** (`src/services/legacyImport.ts`, `useLegacyMigration`, `src/utils/migrationNotice.ts`). `migrateLegacyDreams` runs at provider mount, inside the launch gate, on every launch (single-flight; once `migrated.json` exists later runs do nothing). A line above the list reports the result (counts only, no note text or ids): imported/skipped info lines can be dismissed for the session, failures show a Retry, and a working line shows while the import is still running (for example when the launch cap fired first). It reads `dreams.json`, `dreams.json.bak`, `journals.json` and `dreams/`, and never writes or deletes any of them.

**State ownership.** `AppFlowProvider` owns the notes list (`useNotes`), the open note session (`useNoteSession`), settings, the day marker, `useToday`, the legacy migration, transcription, the launch and resume logic and every trash action (`restoreNote`, `requestDeleteForever`, `requestEmptyTrash`, `pinNote`, `trashNote`), including the `trashBusy` guard (a ref plus state, held from the first tap through the confirm and the operation, and refused while a note is open, a leave is running or the index is unreadable) and `trashNotice`. Wording is in `FLOW_COPY` and `TRASH_COPY`, exported from the provider. The routes only pass these through. Only the provider calls `deleteNoteForever` and `emptyRecentlyDeleted`, and only after the dialog's confirm button; `src/app/trashActions.audit.test.ts` pins this and that no screen, component or route imports a write function from `notesStorage`.

**Storage layout** (everything is under `Paths.document`, resolved on every call because the path can change between app updates on iOS; only the audio **file name** is stored, never a full path):

- `notes.json`: the index, `{ version: 1, notes }`. A note carries its body, timestamps, optional `deletedAt` (in Recently Deleted), pinned state and its recordings.
- `notes.json.bak`: best-effort copy of the previous index, made before a commit only when the current index has content. On Delete forever it is instead rewritten from the new list so the removed text does not survive in it.
- `notes.json.tmp`: the staging file of a commit.
- `notes.corrupt-<timestamp>.json`: a copy of an unparseable index, made at most once per app session. Never deleted by the app.
- `notes/`: audio of notes, one file per recording, never overwriting an existing name.
- `migrated.json`: the import marker (ids and counts only, never note text).
- `settings.json`: `autoOpenDreamCapture` (the on-disk key of "Open a new note on launch"; kept so existing toggles and downgrades are not reset), `onlineTranscription` and `tagSort` (`'alpha'` or `'count'`; anything else, or a damaged file, gives `'alpha'`, fail open). Each key is validated on its own; a damaged file falls back to launch note on and online transcription off. Writes keep unknown keys.
- `no-dream.json`: the day marker, `{"noDreamDate":"YYYY-MM-DD"}` (the latest day marked done; the name and key are legacy). It is written when a new note is first stored and when an empty launch note is left. Fails open: missing, empty, corrupt or wrong shape reads as no marker. The app never deletes it.
- Legacy, read-only (section 7): `dreams.json`, `dreams.json.bak`, `journals.json`, `dreams/`.

**Save order** (`saveNote`, an upsert by id, index work serialized): validate the id and body and that every new recording is a file inside the cache directory (before touching anything); refuse with `NOTE_IN_TRASH` for a trashed note; an emptied note (blank body, no recordings) goes to Recently Deleted with its text kept; copy each new recording from the cache into `notes/` one at a time, never overwriting; then `commitIndex`: write `notes.json.tmp`, read it back and check it parses with the same count, copy a content-bearing current index to `.bak` (a failure does not block the save), move the temp file over `notes.json` with overwrite. If the move leaves the index missing or damaged, recovery reads the temp file, then the backup. The cache files are deleted after a successful save. An unparseable, non-empty index is never overwritten: saves throw `INDEX_UNREADABLE`, the list shows an unreadable message and no launch note opens.

**Where files are deleted.** There are five production `.delete(` sites (all five are literal `.delete(` lines in a grep of `src`; other `.delete(` hits there are test helpers and a `Map` in `NoteListScreen`, not file deletion): `discardRecording` in `recordingFiles.ts` (the cache file of an unsaved recording); in `notesStorage.ts`, `saveNote` twice (the `undoCopies` rollback of copies a failed save just made, and the cache source files after a successful save), `deleteAudioFiles` (stored audio of a note being deleted forever or of a discarded held voice note; never a legacy file or one another note still references) and `scrubCopy` (the fallback when a leftover index copy cannot be overwritten). `CLAUDE.md` has the full deletion rules; do not add a `.delete(` call without the user's approval.

## 4. Decisions made during development

Notes-model decisions only; the earlier dream/journal-app decisions went with that app.

- **Stack**: Expo (SDK 57) + TypeScript, ESLint + Prettier, Jest. Local-only storage; no backend. A development build is required: `expo-speech-recognition`, `react-native-gesture-handler`, `expo-audio` and others are native, so Expo Go cannot load the app.
- **On-device by default.** Transcription runs on the device; audio goes to Apple or Google only when the user turns on "Transcribe voice notes online" and this phone cannot transcribe the note itself. The old live-text feature is removed.
- **Hard cutover** (user-approved): the import is one-time. Anything an older build writes to `dreams.json` after the first import is not imported, and an older build does not know `notes.json`, so notes created in the new app are not visible to it. `src/app/noLegacyWriters.test.ts` proves that nothing reachable from `App.tsx` imports the old writers and that `dreams.json` is named only in `services/legacyImport.ts`.
- **Four routes**. Search was a fifth route by user approval (2026-10-18, "Search returns in 7c") and was replaced by inline search in `NotesRoute` on 2026-10-20 (fewer routes, no new approval needed). Opening a result pushes `Editor` over the list and leaving returns to the same search; `NotesRoute` closes the drawer whenever it loses focus.
- **Delete forever is a scrub**: audio first, then the note's text from `.bak` and `.tmp`, then the index entry (the commit). Row swipe Delete and the editor's Delete move to Recently Deleted without confirm or undo (by decision).
- **The 7b rule, `notes.refresh()`.** Every trash, restore or empty action from the list or Recently Deleted must end with `notes.refresh()` before the UI re-renders (the `useNotes` wrappers refresh after every outcome). This keeps the stale-list case in section 5 unreachable.
- **Voice is an attachment.** Each recording is a card; transcripts live on the recording and are not merged into the body.
- **Checkbox is a toolbar button**, not a tap on the `[ ]` glyph (a `TextInput` has no per-glyph press target).
- **Markdown scope**: headings, bullets, numbered lists, checkboxes, bold, italic. No quotes, links, code or tables.
- **Expo Router is not adopted.** `AGENTS.md` (from the Expo template) says to use it; this app uses React Navigation with the four routes above. Do not change that without asking.
- **System fonts** for now; matching the mockups would need bundled fonts.
- **Storage safety**: copy-then-write-then-delete, a best-effort `.bak`, no overwrite of an unreadable index, one write at a time (decisions are logged in the Steward repo).
- **Wording** is picked by the builders and edited by the user during manual validation. The permission strings in `app.json` stay as they are (user decision, 2026-10-06).

## 5. Accepted behaviours

- **Stale-list open.** Opening a note from a list that is out of date (the note was trashed elsewhere) opens the editor; its first save returns `NOTE_IN_TRASH`, the in-trash banner shows with Leave, and the text stays on screen. If the list's own copy already carries `deletedAt`, `openNote` instead refreshes and shows the alert "This note is in Recently Deleted." With one device and one writer neither can happen, because of the `refresh()` rule.
- **Hard cutover**: later writes by an older build are not imported, and the older build cannot see new notes (section 4).
- **Row Delete has no undo**, and the delete dialogs' voice-note wording does not say that a file shared with another note is kept.
- **Launch cap** opens a new note even if the settings have not loaded; with an unreadable index the list shows instead.
- **Leaving a blank note trashes it.** Leaving a stored note whose body is blank and that has no live voice note moves it to Recently Deleted (step 4 of `useNoteSession.leave`; this includes a blank imported note). The text is kept, so Restore brings it back.
- **Edits after `leave()` starts are dropped.** Once `leave()` begins, further edits are ignored (the `leaving` flag). If the save then fails, the editor stays open with the last state it had before leaving started, without those edits.
- **`trash()` and `leave()` treat cache recordings differently (ruled intended).** After `NOTE_IN_TRASH`, `trash()` discards the unsaved cache recordings (the user chose to delete, so nothing can reference them), while `leave()` keeps them (the user did not choose to delete and they may be the only copy; the files are harmless in the OS cache). Ruling: `reports/2026-10-18-lucid-chunk-7a-1/architect-7a-1-ruling.md`, item 5.
- **Disclosure**: the transcripts of discarded voice notes can remain in `notes.json.bak` until the next index commit (usually the next autosave).
- **Storage limits**: if a commit is killed and every recovery step also fails, the index can be lost. There is no restore-from-backup feature and it would need the user's approval. Killing the app mid-recording leaves a cache file (`useVoiceRecorder` has no unmount cleanup).
- **Downgrade**: an older build ignores `notes.json` and shows only its own data. Data is kept either way.

## 10. Gotchas

- Run `npm run check` (typecheck, lint, format check, tests) before calling anything done.
- In tests, native modules must be mocked. `expo-audio` is mocked per test file; `expo-file-system` uses `src/test/fakeFileSystem.ts` via `jest.mock('expo-file-system', () => jest.requireActual('../test/fakeFileSystem'))`. With React Native Testing Library v14, `render` and `fireEvent` are async: `await` them.
- Storage changes need careful tests with that faithful fake (it models async copy/move, no-overwrite and failure injection). It cannot show real-device `File.move` or `File.copy` overwrite behaviour.
- Use `SafeAreaView` from `react-native-safe-area-context`, not from `react-native`. The app is wrapped in `SafeAreaProvider` in `App.tsx`.
- Install packages with `npx expo install` and check Expo's versioned docs before touching Expo APIs (see `AGENTS.md`).
- Tags are only ever read through `inlineTags` / `scanTags`; do not add another tag parser.
- The user keeps an uncommitted edit to the `android` / `ios` scripts in `package.json` (`expo run:android` / `expo run:ios`) in their own checkout; it must not be committed or reverted.
- On Windows, the PowerShell tool sometimes reports exit code 255 for commands that actually succeeded. Read the output to confirm.
